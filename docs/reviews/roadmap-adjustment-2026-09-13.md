# Roadmap 调整评估与功能梳理

> 日期：2026-09-13。状态：历史产品提案；已由 2026-09-16 的 [需求基线](../requirements/requirements.md)、[目标架构](../architecture/target.md)和[当前 Roadmap](../roadmap.md)取代，不作为当前产品决定。
> 依据：当前源码 `c859fd6`、工作区已有业务评审稿、既有路线图与模型评测，以及 `D:/ds-project/expression-trainer` 的实际数据文件。
> 验证范围：源码核对、少量本地行为复现、词表清点和上游公开说明；不代表本轮完成了真实麦克风、完整界面或线上运行验收。

## 1. 建议的产品主线

把下一阶段的重点放在：**让用户知道哪里值得改、为什么改，并能通过同题重练看到变化。**

推荐顺序：**统一分析口径与交互/UI → 保存训练与前后对比 → 场景和表达方法 → 按收益扩展模型、对话和线上形态。**

三种推进方式的取舍：

| 方式 | 优点 | 代价 | 建议 |
|---|---|---|---|
| 先集中改视觉 | 页眉、按钮、颜色能很快改善 | 保留误导性规则和未闭合的重练流程 | 小项可先做，但不作为全部路线图 |
| 先完成可信的训练闭环 | 规则、反馈、保存和重练互相支持 | 需要先决定少量产品口径 | 推荐作为主线 |
| 同时上新模型、AI 对话和 Web | 功能面扩大 | 同时改变输入、状态、评估和交付，难以判断实际收益 | 拆为独立后续工作 |

原路线图偏工程化交付；七候选 benchmark、三款 streaming 模型和内部安装基线已经完成。此次明确提出模型、词库和产品调整，可以重新讨论这些方向，但不必因此重跑整个 benchmark 或预建平台。公开模型分发和签名继续按既有发布条件处理，不阻塞内部产品体验改善。

| 可选表达理论/方式 | 已有目标、规则、风格文本配置；不同分析入口消费字段不一致 | 做少量“训练方法预设”，设置保存默认值，训练前可选择本次方法 | R3 / 中 |

| 首次启动可粘贴文字 | 已实现；粘贴不依赖模型或麦克风 | 保留独立入口，引导不强迫纯文字用户先完成录音设置 | R1 / 小 |
| 首次启动弹说明 | 已有首次帮助，随后安排录音保留说明 | 减少连续弹窗的负担，说明录音与文字两条路径 | R1 / 小～中 |
| 首次提示录音不保留 | 已有首次录音前确认和帮助说明 | 当前准确表述为“本次运行保留最近五条，退出释放”；加入保存后改成“未主动保存的临时录音退出释放” | R1；R2 同步修订 |
| AI 与本地词典如何配合 | 目前多数是独立输出，仅整篇报告带入汇总统计 | 本地提供可定位观察，AI 结合语境判断并给练习动作 | R1 / 中 |
| 统计、提醒、高亮不在同一段代码 | 情况属实：虽然共享静态词表，但匹配算法、阈值、自定义词支持不同 | 共享同一份匹配结果和字符位置；展示层继续分工，不合成巨型函数 | R1 / 中 |
| 实时反馈、整篇报告、回放分析 | 三条独立 AI 路径；回放只是展示已生成建议，不边播放边推理 | 实时给短提示；结束形成统一复盘；报告与回放展示同一次复盘的不同视图 | R1 定口径并实现必要收敛 |

用词假设：“朗读和复数”按“朗读和复述”理解；“正片报告”按“整篇报告”理解。具体主题、材料和对话形态尚未被用户指定，不作为已确认范围。

## 3. 先重新定义“表达问题”

建议从用户希望听众理解什么出发，使用五类问题。它们是产品分析维度，不是已经验证的心理或能力测量量表。

| 问题类型 | 应检查的内容 | 不应直接判错的情况 |
|---|---|---|
| 清楚具体 | 指代是否清楚，关键条件/数字/例子是否缺失 | 使用“这个”“很好”等普通词，本身不构成错误 |
| 结构与重点 | 核心观点能否识别，信息顺序是否支持当前任务 | 自然聊天不必每句先给结论；朗读不评分原创结构 |
| 简洁与连贯 | 无意义重复、过多铺垫、连续口癖是否干扰理解 | 表示真实时间顺序的“然后”，必要的总结和复述 |
| 准确与证据 | 结论是否被理由支持，措辞确定程度是否匹配证据 | “可能”“尚不能确定”等合理保留，以及真实情绪 |
| 听众与场景适配 | 背景解释、术语、语气是否符合对象和目的 | 日常口语不因“不够书面”被扣分，委婉不自动等于软弱 |

每条重要建议应包含：**原句证据 → 为什么可能影响当前表达目标 → 保持原意的改法 → 下一次可执行的练习动作**。全篇优先呈现一到三个重点，允许给出“这一点无需修改”。

例如：“根据现有证据，故障可能与网络有关。”可以建议补充已有证据，但不能要求把“可能”直接删成确定结论，也不能编造测量数字。普通词换成更强烈或更书面的词，不一定更准确。

目前 AI 接收文字，回放另附片段 ID 和时间，不接收原始音频。因此本轮可以讨论文本组织和词语使用，不能承诺已能评价发音、音色、重音或真实语音情绪；现有时长也不足以直接证明停顿质量。

### 已复现的具体问题

通过当前模块直接运行以下短句，确认了需要调整的判断来源：

| 输入 | 本地统计 | 字幕高亮 / 下游提醒 | 影响 |
|---|---|---|---|
| 我觉得这个方案可行 | “我觉得”为犹豫词 | 高亮只把“觉得”归为笼统词 | 同一表达出现不同标签 |
| 咱就是说这个办法可行；自定义口癖“咱就是说” | 识别完整自定义口癖 | 高亮拆成“就是”和“说” | 自定义设置未贯通 |
| 先检查网络，然后重启服务 | “然后”计入填充词 | 同样高亮为填充词；这一句未达到两次提醒阈值 | 数字只证明词出现，不能证明它冗余 |
| 根据现有证据，故障可能与网络有关 | “可能”计入犹豫词 | 录音路径命中一次即生成“直接说”提醒 | 提醒可能损害准确性 |

另有两套本地提醒阈值：界面填充词≥2、犹豫词≥1；词库模块生成的建议分别为≥3、≥2，而该建议数组未被主界面消费。先明确一个有效输出路径即可，不需要新建规则引擎。

## 4. 本地、AI 和三个反馈时机如何配合

| 层次 | 职责 | 输出 | 限制 |
|---|---|---|---|
| 本地分析 | 词形匹配、次数、字符位置、文本字数和真实录音时长 | “候选口癖出现几次、位于哪里”等可核对观察 | 匹配不等于错误；不靠词表得出整篇质量分 |
| 实时 AI | 根据本次目标和近期上下文，选择最值得注意的一件事 | 一条简短、可立即执行的提醒；也可以没有提醒 | 不反复评价全篇，不持续打断表达 |
| 结束后的复盘 | 根据完整文字、目标、必要统计与片段证据给出重点和练习动作 | 一份归属于本次训练的复盘结果 | 不能凭措辞自信度推断内容真实性 |
| 整篇报告 | 展示复盘重点、证据、建议和统计 | 可阅读、保存的全篇结果 | 与片段建议保持一致 |
| 回放分析视图 | 播放至对应片段时显示复盘中关联的建议 | 当前片段、原句、修改建议 | 播放和拖动不重新发 AI 请求 |

建议的数据走向：输入形成逐字稿和片段 → 本地匹配结果供统计、高亮及中性提示共用 → AI 结合这些观察与上下文进行判断 → 完成后的同一份复盘供报告和回放展示 → 保存后用于同题重练比较。

“共享结果”比“放进同一个函数”更重要。本地匹配建议提供原文字符起止位置；统计计次、字幕绘制和提示排布仍各司其职。匹配冲突和自定义词优先级在这一处明确。

现有“表达密度”只是扣除填充/犹豫词字符后的比例，不是语义信息量。建议从主评分中移出，保留时用“词表统计”解释，或改为直接呈现命中比例，避免鼓励删除合理限定语。对比也不以这个比例的上升直接宣称进步。

实时 AI 目前按新增30个字符串字符触发，最近500字符之外的内容不可见，模板中的时间/主题/历史观点也没有实际传入。应先收窄无输入支撑的提示，再根据完整句和冷却间隔调整频率；只有确需判断跑题或时间目标时，补本次主题和时长，不预建长期记忆。

AI 开关建议：默认关闭；配置模型不隐式开启。开启后才允许实时、粘贴后和结束后的自动分析；整篇报告和重新分析也必须尊重关闭状态。关闭时取消在途请求并忽略迟到结果，保留已有结果但标明为此前生成。本地录音、转写、统计和回放继续可用。第一版用一个总开关即可，复杂的实时/结束分开配置按反馈再决定。

用户开启 AI 后，建议结束时生成一次完整复盘；再次查看报告或播放片段复用结果，只有主动重新分析才替换。本次所用模型、规则和训练方法应随结果记下，后续切换设置不会把旧结果伪装成新设置的产物。

## 5. 交互和 UI 一起确定的最小范围

建议主训练页维持稳定分区：顶部显示当前训练与必要入口；内容区负责字幕/逐字稿；反馈区负责当前重点；底部是录音或回放操作。帮助中放说明、反馈和诊断；规则负责“怎么练”，设置负责模型、外观和默认偏好。

| 情境 | 应让用户知道什么 | 操作和显示建议 |
|---|---|---|
| 首次打开 | 可录音，也可直接粘贴；语音模型正在准备 | 一份简短入门说明，呈现两条入口；录音保留说明在录音使用前可确认，帮助中长期可查 |
| 模型准备 | 加载已安装模型，或缺少模型需安装 | 显示具体阶段和恢复入口；粘贴仍可用，不能把全应用锁死 |
| 开始录音中 | 正在建立本次录音 | 阻止重复开始和覆盖内容的操作；失败回到之前可用视图 |
| 录音/暂停 | 当前是否正在采集 | 绿色计时加文字/图标状态；暂停不计入有效录音时长 |
| 结束收尾 | 正在整理尾部文字 | 可立即切换到结束后的布局；同一模型/会话释放前不接受第二次录音，按钮显示准备状态 |
| 文字分析 | 只有文字，没有音频时长 | 标签“文字分析”，隐藏回放和语速；切去录音按已有用户选择确认中断分析，旧结果不得回写 |
| 回放 | 当前听到哪里，总长多少，建议属于哪个片段 | 固定显示 `01:23 / 03:40`；播放、暂停、拖动同步；切去新录音不重复询问 |
| 无识别文字的录音 | 音频存在，未识别出文字 | 保留记录，标“无识别结果”，允许听录音；不要显示虚构的分析 |
| AI 关闭/无配置/处理中/失败 | 是否启用与是否可用是两件事 | 就近显示真实状态，失败可打开设置/重试；不要把“无建议”写成“内容为空” |
| 保存或删除 | 当前是临时记录还是已保存训练 | “清空当前视图”和“删除已保存训练”语义明确；不把复制等同于已保存 |

历史 `ui-state-audit-2026-09-02.md` 记录过“准备中全部不可用”等用户选择。本文按当时要求区分“应用预加载模型”和“真正启动录音”：前者允许粘贴，后者限制冲突操作；不把旧状态表机械套回当前版本。后台收尾可先改变视觉，但不意味着已经支持多个录音会话并发。

先在现有 CSS 主题变量中收敛样式和控件状态，不要求引入新的前端框架或组件库。原生 Windows 标题栏是否需要额外窗口配置，与页面顶部颜色分开验证。

## 6. 保存、清单和对比怎样做才有训练价值

建议先支持本地手动保存，不默认建设账号和云同步。

- **临时记录**：沿用运行期最近五条，明确未保存；删除/淘汰/退出释放临时音频。
- **已保存训练**：用户主动保存文字、统计和复盘，并明确选择是否包含音频；重启可打开、重命名和删除。文字输入也能保存成训练记录。
- **保存内容**：本次主题、训练任务、时间、逐字稿、相关统计、报告及片段建议；必要时附音频和时间轴。记录所用 ASR/AI 模型与规则/方法版本，只为解释对比，不保存 API Key 或复制完整设置。
- **第一种对比——同题重练**：选择前后两次训练，比较本次目标是否改善、原句与改法、可比统计；下一次默认带入上一轮选中的一个重点。
- **第二种对比——模型分析结果**：同一份逐字稿保留 A/B 两次分析，分别显示来源；与“人的训练进步”分开。首版不自动并行调用所有模型。

无音频的保存记录应明确“文字记录，无法回放”；用户选择保存音频时，不能持久化只在当前进程有效的 Blob URL。根据当前规模，使用现有文件存储方式即可，不预设数据库。

比较前后两次时，优先同题、相近时长、同一方法和规则；ASR 模型改变可能改变口癖保留程度，AI 模型或提示词改变也可能改变评价。同一量表下的具体观察可以展示变化；条件不同则并排展示并标明差异，不显示未经校准的“能力提升百分比”。

现有全篇报告只保存在当前页面字段，没有归入每条录音记录；回放分析则已经归属于录音。这一归属差异要先补齐，否则“保存本次训练”可能保存错报告。

## 7. 内容、训练任务和表达方法

这三个概念应分开：**输入方式**是录音/粘贴；**训练任务**是朗读/复述/讲述/观点表达；**参考材料**是原文、题目或要点。粘贴一段“待分析的逐字稿”和粘贴一段“供复述的参考材料”也要有不同入口语义。

| 任务 | 最小输入 | 复盘重点 | 初期范围 |
|---|---|---|---|
| 描述一件事 | 题目、听众、时间目标 | 事情经过、重要细节、自己的行动和结果是否清楚 | 建议首个训练样板，可完全复用录音主流程 |
| 复述 | 原始材料或要点＋用户复述 | 关键点覆盖、事实偏移、组织和简洁 | 先支持用户自贴材料；评价忠实度必须拿到原文 |
| 朗读 | 参考原文＋录音 | 遗漏、重复及节奏观察；识别差异需人工可核对 | 不宣称提供发音评分；ASR 错字不直接判成朗读错误 |
| 观点表达 | 一个问题＋立场/目标 | 观点、理由、例子与收束 | 配合少量结构预设 |

建议首批仅提供少量任务卡和用户材料输入，不启动大规模题库抓取。默认使用“自然表达”；可选两到三种结构化预设，例如“观点—理由—例子—回扣”和 STAR（情境、任务、行动、结果）。STAR 常用于行为经历的讲述与面试回答，适合“描述一件事”，不必成为所有表达的强制模板。[STAR 的官方使用说明](https://governmentdigitalanddatahub.campaign.gov.uk/join/government-digital-and-data-careers/prepare-for-your-interview/starr-and-car-techniques/)

设置中保存默认方法，训练前显示本次方法并允许覆盖；反馈、复盘和保存结果一致使用本次选择。第一版把它们作为训练提示和评价关注点，不开发理论插件系统，也不生成不同理论间可直接比较的总分。

## 8. ds 词库评估与最小测试

实际目录：`D:/ds-project/expression-trainer`，并非字面上的 `D:/ds_projects`。已核对 `docs/词库选型调研报告.md`、`data/wordlists/README.md`、六个种子表和两个 JSON 文件。

按非空、非注释行解析，TSV 以首列词条去重，得到：

| 资源 | 实际条目 | 建议 |
|---|---|---|
| 语气词 | 60行、58个不同词条 | 先作为候选观察，不因出现语气词直接判冗余 |

当前有效静态规则为填充词16项、犹豫词14项、笼统词替换入口20项。参考报告的“650词”“数千词”等描述不能当作已落盘事实，其关于外部库规模与许可的旧说明也未在本轮重新认证。

最小测试集要回答“是否更少误伤、是否保留真实问题发现能力”，而不是只检查词条能否加载。先用一小组人工确认的口语片段覆盖：正常时间连接词、合理不确定性、真实重复口癖、指代词、委婉表达、自定义词、长短词重叠、中英数字与标点、明显 ASR 错词；每项同时检查匹配位置、统计和高亮是否一致。

扩表前后记录误报、漏报和建议是否改变原意；先修用户会遇到的误报，再增加候选。不能把停用词列表直接当“应该删除的口语词”，也不为这批小词表预建新分词平台或大语料基础设施。

## 9. 模型、AI 对话与线上版本的边界

### 9.1 未接入模型

“语音识别模型”和“生成分析的 AI 模型”是两件事。前者把音频变文字，后者评价文字；设置和状态中要分别命名。这里将“之前未添加的模型”主要映射到既有 ASR 待办；若指新的 LLM 服务，当前多配置和自定义兼容后端应先验证能否直接满足。

| 模型 | 项目证据和建议 |
|---|---|
| Zipformer Large / Small、Paraformer | 已在产品中，保留当前流式主流程 |
| SenseVoiceSmall 2024 | 七候选普通话测试 CER 最低，优先作为可选整段复盘模型评估；不伪造实时 partial |
| FireRedASR2 | 既有后续计划；本次普通话评测没有显示比 SenseVoice 更明确的收益，重排在其后，具体语言收益确认后实施 |
| SenseVoiceSmall 2025 | 现有评测中普通话不优于2024版；粤语需求明确后再做针对性验证 |
| Qwen3-ASR 0.6B | 现有结果显示资源需求较高；待多语种/方言等具体需求再决定，不作为默认新增 |

既有 ADR 的 utterance 产品路径采用最多五分钟的缓冲和停止后解码；BM-04 又提出过 VAD 切句方向。两者不是同一个交互方案。首批建议采用边界更明确的“短录音结束后识别”；若需要边说边按句返回，再单独明确 VAD、延迟和片段时间轴，不能只在设置中增加一个型号。

模型评测原本测普通话转写 CER，不证明对口癖、重复和训练片段的保留是否足够。实际接入时补少量会改变产品判断的真实训练样本，关注口癖保留、结尾文字、延迟和资源；不要因新增选择按钮重跑所有无关评测。以上模型比较仅引用项目已完成的冻结集结果，不外推为最新通用排名。

### 9.2 AI 直接对话

可以做，但分三层：围绕本次报告追问 → 文本轮流模拟面试/沟通 → 语音轮流或实时对话。建议先实现第一层，让用户询问“这句为什么不清楚”“给我一个保持原意的改法”，复用现有 LLM 能力，并使对话关联本次训练。

语音对练还涉及角色轮次、语音合成、结束判断、打断和可能的回声问题；当前单人录音分析流程不能直接等同于对话系统。未明确需要这些能力前，不提前建设。

### 9.3 线上版本

本地远程配置确认：当前 origin 是 `morigejile/expression-trainer-pro`，upstream 是 `fxy2311-youyou/expression-trainer`。后者 README 也声明 `exprtrain.online`，因此本仓库的链接不足以证明该站属于当前分支，或已经包含本分支的功能。[上游 README](https://github.com/fxy2311-youyou/expression-trainer#readme)

本轮未能取得线上站点可用页面，不判断其可用性、技术栈、当前功能或所有权，也不据此判断网站已下线。

需要明确三个不同交付目标：

| 目标 | 对当前项目的含义 |
|---|---|
| 让其他人下载桌面版 | 提供下载和使用入口，沿用桌面打包/公开发布轨道 |
| 让当前分支的产品在浏览器运行 | 独立 Web 交付，需要明确麦克风、转写执行位置、AI 凭据、存储和运行成本 |
| 与上游现有在线版对齐 | 先确认对该站点/代码的控制范围，再核对功能差异和可复用内容 |

在用户进一步明确前，不假设拿得到上游站点代码或部署权限。浏览器版可先考虑文字分析等最小切片，再选择浏览器本地识别或服务端识别；不能把现有 Electron native 模型直接视为浏览器可运行模型。当前阶段只安排范围确认，不提前引入后端、账号、云同步或部署平台。

## 10. 建议写入下一版 Roadmap 的阶段

| 阶段 | 核心交付 | 依赖和完成判断 |
|---|---|---|
| R1：分析可信、体验一致 | 统一问题定义；本地命中/统计/高亮一致；处理误导提醒；明确三类反馈并收敛复盘结果；AI总开关；主题、帮助/诊断、计时和状态优化；首次流程验收 | 同一句话不出现矛盾标签；AI关闭后无新分析请求；无模型也可粘贴；录音/停止/回放状态清楚。小视觉改动可先交付，不等待全部规则工作 |
| R2：保存与同题对比 | 已保存训练、可选音频、清单与删除；报告归属；两次练习比较；一个重点带入下一次 | 依赖R1稳定的分析含义和结果归属；重启后恢复正确记录，保存结果不被五条淘汰，同题对比能解释变化 |
| R3：场景化训练 | 描述事情作为首个样板，随后复述/朗读；少量方法预设；筛选后的词库扩充 | 本次任务/材料/方法贯通输入、复盘和保存；不以书面化或强硬措辞作为通用成功标准 |
| R4：按需求扩展 | SenseVoice优先，其他模型按收益；报告追问，再考虑语音对练 | 每项单独说明解决什么现有缺口；复用稳定闭环，不把所有候选捆为一批 |
| Web：独立范围与交付 | 现在即可确认目标、站点归属和部署范围；实现排期随后确定 | 不把上游站点当当前分支线上版，不要求先重写桌面架构 |
| 公开桌面交付：延续既有轨道 | 模型公开再分发、签名、目标平台证据 | 沿用现有发布条件；只阻塞相应公开制品，不阻塞内部功能开发 |

第一批具体可拆为：移除顶部重复诊断并统一样式；绿色计时与回放双时长；AI总开关与真实状态；修复统计/高亮的两个已复现分歧；调整“可能→直接说”等无语境提醒。与此同时把结束复盘、报告和回放的结果归属定清，再进入保存实现。

需要选择、但不妨碍当前梳理的事项：线上版本的具体含义；保存对比主要看个人进步还是多模型差异；首个训练场景是否采用“描述一件事”；AI默认关闭和保存内容选择是否符合使用习惯。本文分别给出建议，不将其写成已确认产品决定。

本提案通过后，应将执行中的任务吸收到 `docs/roadmap.md`，将最终产品行为同步到需求基线；已完成和仍未完成的首次启动事项重新分开。无需为每个视觉小项创建独立设计文档或发布门禁。
