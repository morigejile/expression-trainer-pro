## 1. 这份文档解决什么问题

`ExpressionTrainer` 没有显式的界面状态概念。控件长什么样由约 8 个布尔/引用字段的组合隐式决定，
而写入 DOM 的位置散落在 12 处以上：`classList` 出现 66 次、`hidden` 59 次、`.disabled` 26 次。

后果是每新增一条功能路径（录音策略确认、回放、粘贴分析），都必须回到所有已有分支补一遍控件处理，
漏补的地方不会报错，只会在特定操作顺序下表现为按钮状态不对。本文把「隐式组合」显式列成表，
用于三件事：

1. 审阅现状与期望的差异，差异即待修缺陷清单（第 5 节已列出 9 条候选）；
2. 作为把散落写入收敛成单一 `computeUiState()` 的验收基准；
3. 新增功能时先改表再改代码，避免状态组合继续隐式增长。

## 2. 状态由哪些字段隐式决定

界面状态没有单一字段，而是下列字段的组合（`src/app.js:67-110`）：

| 字段 | 含义 | 谁在写 |
|---|---|---|
| `asrStartAttempt` | 非 null 表示一次启动尝试进行中 | `startRecording` / `failActiveRecording` / `clearAll` |
| `isRecording` / `isPaused` | 录音进行中 / 已暂停 | `startRecording` / `pauseRecording` / `teardownRecordingCapture` |
| `recordingStopOperation` | 非 null 表示停止流程进行中 | `stopRecording` / `completeRecordingStop` |
| `viewingTrainingRecordId` | 非 null 表示正在查看某条训练记录 | `selectTrainingRecord` / `clearAll` / `analyzePastedText` |
| `pasteAnalysisPending` | 逐字稿分析进行中 | `setPasteAnalysisPending` |
| `reportRequestPending` | 报告生成中 | `generateReport` |
| `playbackAnalysisGeneration` | 回放分析的代际，用于作废过期结果 | 六处自增 |
| `activeModal` | 当前打开的弹窗 | `openModal` / `closeModal` |

本文据此归纳出 8 个状态。它们是**推导结果，不是代码里的枚举**：

| 编号 | 状态 | 判定条件 |
|---|---|---|
| S0 | 空闲·无内容 | 初始，或 `clearAll()` 后，或删光记录后 |
| S1 | 准备中 | `asrStartAttempt !== null`（含录音策略弹窗与 ASR 启动） |
| S2 | 录音中 | `isRecording && !isPaused` |
| S3 | 已暂停 | `isRecording && isPaused` |
| S4 | 停止中 | `recordingStopOperation !== null` |
| S5 | 回放查看 | `viewingTrainingRecordId !== null` |
| S6 | 粘贴分析中 | `pasteAnalysisPending === true` |
| S7 | 空闲·粘贴结果 | 有 `fullText`，无 `viewingTrainingRecordId`，无录音会话 |

S6 与 S1 是**叠加态**：它们只改动少数控件，其余控件承接进入前的状态。表中记为「不变」的格子，
正是当前缺陷的集中位置。

## 5. 已发现的不一致（9 条，待审阅）

前 6 条属交互逻辑，收敛状态机时一并处理；后 3 条独立，可单独修。

**⚠️1 准备中与分析中不复位内容区。** `startRecording` 只改动 `btnStart` / `btnPaste` / 状态条（291-293），
`finishTrainingPreparation` 回滚时同样只碰这三个（1237-1241）。从 S5 点「开始」进入 S1，回放控件、
报告、复制、保存、清空全部保持可见可点，此时它们指向的是即将被替换的上一条记录。

**⚠️2 「禁用控件」与「运行时拦截」两种范式混用。** 录音期间粘贴按钮被 `disabled`（455），
而逐字稿分析期间开始按钮不禁用，改由 `startRecording` 开头弹提示「逐字稿正在分析，请稍候」（285-287）；
`openPasteModal` 同样用拦截而非禁用（1685-1694）。同一类约束两种表达，用户看到的可点性不一致。

**⚠️3 `btn-start` 隐藏时仍在切换 `disabled`。** 442 行隐藏后，456 行又置 `disabled = false`；
292 行置 `disabled = true` 时按钮可见。可见性与可用性两个维度没有分离，读代码时无法从单点判断按钮状态。

**⚠️4 「不可用」有两种表达。** 停止流程中三个按钮保持可见但 `disabled`（663-665），
其余状态一律用 `hidden`。两种表达在同一屏内混用。

**⚠️5 回放态清空按钮无条件显示。** `refreshPlaybackControls` 对报告/复制/保存按 `fullText` 判空
（1346-1348），唯独清空无条件 `remove('hidden')`（1349）；而 `finishOwnedAsrStopAndUi` 在其后又对四者
统一按 `fullText` 判断（763-769）。一条全程无 ASR 结果的空记录会落到「只有清空可见」的组合。

**⚠️6 计时器在粘贴模式不复位。** 全文只有 1577、1672 两处写 `00:00`，`analyzePastedText` 不在其中。
「录一段音（计时器停在 01:23）→ 粘贴逐字稿分析」后，计时器仍显示 01:23，而 `stats.duration` 已置 0（1774），
同屏两个时长口径矛盾。

**⚠️7 `clearAll` 绕过 `closeModal` 关报告弹窗。** 1677 行直接 `reportModal.classList.add('hidden')`，
未清 `activeModal`、未恢复 `modalOpener` 焦点，与 `closeModal`（1201-1207）行为不一致。

**⚠️8 图标按钮用 `textContent` 做临时反馈会吃掉 SVG。** `copyOriginalText` 把
`<svg>+复制`（`index.html:86`）整体覆盖为 `✓ 已复制`，1.5 秒后写回纯文本 `📋 复制`（1611-1613），
图标不再回来、且降级成 emoji。`btn-copy-report`（190-196）与 `exportDiagnostics`（214-219）同样。

**⚠️9 报告弹窗内联硬编码颜色，绕开设计变量。** `renderReport` 用 `#E5007E`（1090-1094）、
加载文案 `#666`（1041）、错误 `#ff6b6b`（1063、1154）。`styles.css` 已定义 `--color-accent: #c96c98`、
`--color-error: #d8787f` 并有浅色主题（28 行起），这几处不跟随主题切换。

## 6. 需要产品判断（Product-TBD）

代码给不出答案，收敛状态机前需要定：

1. **S1 准备中**允许操作哪些控件？现状是除开始/粘贴外全部可用（⚠️1）。
2. **S6 粘贴分析中**能否开始录制？现状是可点击但被提示拦截（⚠️2）。
3. **S5 回放查看时点开始录制**是否需要二次确认？现状不确认——`startRecording:312` 的确认条件显式排除了
   `viewingTrainingRecordId`，看历史记录时直接开始新录制并替换视图。
4. **空文本训练记录**（ASR 全程无结果但录到音频）在 S5 应该呈现成什么样（⚠️5）。
5. **S4 停止中**是否允许再次点击停止/暂停？现状禁用（⚠️4）。

结论/答复：
1.准备中整体功能无法使用，全部不可用就好
2.粘贴分析中可以开始录制，就是是否要跟用户确认下停掉分析，开始录制，以免误操导致的开始录制
3.回放查看是可以直接开始录制，无需二次确认
4.采用终端中沟通的B方案：“- B 留但标记 —— 下拉标注「(无识别结果)」，字幕区放一句说明”
5.采用终端中沟通的B方案：“- B 立刻切成结束后布局 —— 点完停止马上显示「开始/粘贴」，收尾在后台跑，状态条提示进行中。”

## 7. 收敛方向

目标是把上述所有写入收敛到一个纯函数：

```js
computeUiState(state) -> {
  btnStart:  { visible, disabled },
  btnPause:  { visible, disabled },
  // …每个受管控件一条
  timer:     { text, active },
  status:    { text }
}
```

调用方只改状态字段再调 `render()`，不再直接触碰 `classList` / `disabled`。

建议分批收编，每批可独立验收与回滚：

1. 主控区 6 个按钮（第 3 节整表）——覆盖 ⚠️1~⚠️4；
2. 内容区工具栏与记录下拉（复制/保存/清空/下拉）——覆盖 ⚠️5；
3. 计时器与两条状态文案——覆盖 ⚠️6；
4. 弹窗开关统一走 `openModal` / `closeModal`——覆盖 ⚠️7。

⚠️8、⚠️9 与状态机无关，可随时单独修。
