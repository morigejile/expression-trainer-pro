# Expression Trainer 响应式主题与双布局设计

日期：2026-08-31
状态：Implemented（UI-01/UI-02）；2026-08-31

## 1. 目标

本设计对 Expression Trainer 的主界面、设置页和训练规则页进行渐进式视觉升级，同时保留现有 Electron 与原生 HTML/CSS/JavaScript 技术栈。

目标如下：

1. 默认视觉简约、专业、低干扰，适合长时间表达训练。
2. 字幕是第一视觉层级，实时反馈是第二层级，训练洞察是第三层级。
3. 字幕与实时反馈在训练期间始终处于可视范围。
4. 提供四套内置主题，以及两种可切换布局。
5. 适配 FHD、2K、4K 屏幕及常见 Windows 显示缩放。
6. 主题或布局切换不得重建训练状态、丢失内容或打断录音。

## 2. 非目标

本轮不包含：

- React、Vue、Vite、TypeScript 或其他前端框架迁移；
- 第三方主题、图标或动效依赖；
- 用户自定义颜色、自由拖拽、侧栏缩放或布局编辑器；
- 新的表达指标、反馈类型或训练功能；
- 截图审批系统、视觉回归服务或新的发布门禁；
- 对 Audio、ASR、LLM 或 benchmark 行为的改造。

## 3. 总体方向

界面采用“专注型表达教练”气质。视觉减少霓虹、闪烁和装饰元素，以清晰的排版、克制的表面层次和稳定的信息位置建立产品感。

主界面的信息优先级固定为：

1. **字幕**：当前表达内容、历史字幕和 interim 文本；
2. **实时反馈**：持续可见的建议流；
3. **训练洞察**：填充词、犹豫词、笼统词和表达密度。

这个优先级适用于两种布局及全部主题，不因窗口变大而增加新的信息区块。

## 4. 主题系统

### 4.1 内置主题

| 标识 | 名称 | 类型 | 用途 |
| --- | --- | --- | --- |
| `graphite` | 石墨 Graphite | 深色 | 默认主题；中性、安静、低干扰 |
| `midnight` | 深海 Midnight | 深色 | 深蓝夜间主题；更沉浸但不过度发光 |
| `paper` | 纸张 Paper | 浅色 | 暖白阅读主题；适合长时间使用 |
| `mist` | 晨雾 Mist | 浅色 | 冷灰浅色主题；适合办公环境 |

### 4.2 实现边界

主题使用 CSS 自定义属性和根节点 `data-theme` 属性。四套主题共用组件规则，只覆盖语义 token：

- 页面背景、面板背景与次级表面；
- 主文字、次级文字与弱化文字；
- 边界、焦点环和阴影；
- 品牌强调色；
- 成功、提醒、错误及三类表达高亮色；
- 主按钮与次级按钮状态。

主题不得复制完整组件样式，也不得通过 JavaScript 动态拼接内联 CSS。

## 5. 布局系统

两种布局共用完全相同的 HTML/DOM、元素 ID、字幕节点、反馈节点和训练状态。根节点通过 `data-layout` 切换 CSS 布局变量和定位规则。

### 5.1 A：教练侧栏

标识：`coach-rail`
用途：默认布局

- 字幕舞台占主要宽度。
- 右侧教练栏长期显示实时反馈。
- 训练洞察压缩为教练栏底部的紧凑数据条。
- 默认比例约为字幕 72%、实时反馈 20%、训练洞察 8%，具体像素宽度受响应式上限约束。
- 该布局强调结构稳定和连续阅读。

### 5.2 D：专注 HUD

标识：`focus-hud`
用途：更沉浸的可选布局

- 字幕形成中心舞台。
- 实时反馈作为固定在右侧的 HUD 层长期可见，不随字幕滚动消失。
- 训练洞察缩为边缘指标，不与反馈争夺面积。
- HUD 只能覆盖舞台预留的安全区，不得覆盖字幕正文。
- 接近最小窗口宽度时，HUD 自动收敛为固定右栏，仍使用同一 DOM，不切换模板。

### 5.3 运行时切换

A/D 可在训练过程中即时切换。切换只改变根节点属性，不移动或重建 DOM，因此必须保持：

- 当前录音、暂停或结束状态；
- session、timer 和统计值；
- 已生成的字幕与 interim 文本；
- 实时反馈内容；
- 字幕与反馈滚动位置；
- 待完成的分析和 LLM 请求。

## 6. 主窗口与响应式规则

### 6.1 初始窗口尺寸

主窗口不再固定为 1200×800。启动时依据 Electron 提供的主显示器逻辑工作区计算初始尺寸，从而自然适配 Windows 缩放：

- 初始宽度约为工作区宽度的 86%，限制在 1200–1920 逻辑像素；
- 初始高度约为工作区高度的 88%，限制在 720–1200 逻辑像素；
- 窗口自动居中；
- 最小窗口尺寸为 960×640；
- 用户仍可最大化和全屏。

不通过物理像素硬编码识别 FHD、2K 或 4K，也不新增窗口尺寸持久化设置。

### 6.2 响应式区间

| 逻辑窗口宽度 | 模式 | 行为 |
| --- | --- | --- |
| 960–1279 | 紧凑 | 减少边距；D 的 HUD 收敛为不遮挡字幕的右栏 |
| 1280–1599 | 标准 | 使用默认信息密度和字号 |
| 1600–1919 | 宽屏 | 适度增加字幕字号、留白和反馈宽度 |
| 1920 以上 | 超宽 | 内容宽度封顶并居中，不无限拉伸 |

### 6.3 排版伸缩

- 字幕字号使用 `clamp()` 在约 26–40px 之间平滑变化。
- 字幕文本设置合理最大行宽，2K/4K 下不横跨整个窗口。
- 实时反馈区域弹性变化，但约束在 300–460px 范围。
- 间距、面板内边距和控制按钮随窗口宽度适度增长。
- 4K 增加留白和阅读舒适度，不增加卡片或数据密度。

## 7. 视觉规范

### 7.1 字体与层级

- 使用系统字体，不下载或捆绑新字体。
- 字幕是最大字号和最高对比度内容。
- 实时反馈正文约 13px，反馈标题和关键建议适度加重。
- 训练洞察约 11–12px，以短标签和紧凑数字呈现。
- timer 和统计数字使用系统等宽字体。

### 7.2 表面与颜色

- 使用低对比度表面层次、1px 边界和克制阴影。
- 不使用大面积渐变或循环发光。
- 强调色只用于主要操作、录音状态和少量重点。
- 三类表达问题继续使用不同语义颜色，但在各主题中控制饱和度并保证可辨识。
- Graphite 使用柔和玫红作为品牌强调，不延续高亮霓虹洋红。

### 7.3 图标与装饰

- 移除 DJ 少女装饰、字幕闪烁边框和循环呼吸效果。
- 将 emoji 操作图标替换为统一的单色线性 SVG；SVG 随项目内联，不引入图标库。
- 顶栏显示简短名称“表达训练”；完整产品名继续用于窗口标题和关于信息。
- 主要按钮使用图标与文字；次要工具可以只显示图标，但必须保留 tooltip 和可访问名称。

### 7.4 动效与可访问性

- 普通悬停和布局切换使用 120–180ms 的短过渡。
- 不使用持续闪烁、漂浮或强呼吸动画。
- 录音状态仅使用小型状态点或克制的透明度变化。
- 保留并扩展 `prefers-reduced-motion` 支持。
- 键盘焦点必须清晰；浅色和深色主题下的正文、提示和错误状态均应保持足够对比度。

## 8. 设置与状态模型

### 8.1 AppearanceStore

外观使用独立的 Electron `userData/appearance.json`，schema version 1：

```json
{
  "schemaVersion": 1,
  "theme": "graphite",
  "layout": "coach-rail"
}
```

Main 中的小型 AppearanceStore 负责读取、校验、同盘原子写和规范化广播。允许值固定为四个主题标识和两个布局标识；缺失、未知或损坏值回退为 Graphite＋A。它不读取或写回 LLM provider 配置、ASR selection 或训练状态，也不使用 `localStorage` 建立第二份来源。

### 8.2 设置页交互

设置页新增独立“外观”区域：

- 显示四个主题选择项和两个布局选择项；
- 点击后即时预览并立即持久化；
- 外观保存不触发 LLM 连接测试；
- 现有 AI 服务配置继续保持“保存设置”和“测试连接”两个独立动作；
- 外观区域增加后设置页允许纵向滚动。

### 8.3 窗口同步

保存外观后，Main 进程通过字段明确的 Appearance IPC 广播规范化后的外观设置：

- 主窗口同时应用主题和布局；
- 设置页与训练规则页只应用主题；
- 主窗口内的粘贴与报告弹窗继承主窗口主题。

每个页面在 HTML/CSS 根节点提供 Graphite 默认值，脚本读取后再覆盖。读取缓慢或失败时页面保持可见，不为避免主题闪烁而长时间隐藏整个页面。

## 9. 错误处理

- `appearance.json` 不存在时直接使用默认外观，并在首次用户保存时创建。
- 未知主题或布局回退到默认值。
- 设置读取失败时使用默认外观并显示页面，不允许永久空白。
- 外观保存失败时恢复上一个已保存选择，并在设置页显示非阻塞错误信息。
- 单个窗口同步失败不得影响其他窗口或训练流程。

## 10. 验收标准

1. 新安装默认显示 Graphite＋A。
2. 四个主题和 A/D 均可即时切换、持久化并在重启后恢复。
3. 字幕在两种布局中始终是第一视觉层级。
4. 实时反馈在训练期间始终处于可视范围，且比训练洞察更突出。
5. D 的 HUD 在任何支持的窗口尺寸下都不覆盖字幕正文。
6. 训练过程中切换主题或布局不丢失训练状态、内容和滚动位置。
7. 主窗口在 FHD、2K、4K 及常见 Windows 缩放下使用合适的初始尺寸和信息密度。
8. 主窗口、设置页、训练规则页和弹窗使用一致主题。
9. 移除 emoji、DJ 少女和循环发光后，现有操作仍可识别且具备可访问名称。
10. 不增加前端框架、主题依赖、图标依赖或视觉审批系统。

## 11. 验证范围

### 11.1 自动化

- 增加 AppearanceStore 聚焦测试：默认值、合法保存、非法值回退、原子发布失败和 future schema 显式保存保护。
- 扩展 Electron smoke：主窗口、设置页和训练规则页能够应用并同步主题。
- 使用现有 Fake ASR 流验证录音中切换布局不会重建训练状态。
- 保持既有安全渲染、LLM provider 设置和产品流程测试通过，并证明外观保存不调用 LLM 配置 IPC。

### 11.2 人工视觉检查

- 四个主题分别检查一次 A。
- Graphite 和一个浅色主题分别检查一次 D。
- 在代表性 FHD、2K、4K 逻辑窗口尺寸，以及最小尺寸和全屏状态检查布局。
- 检查字幕、实时反馈、训练洞察的固定视觉顺序。
- 检查 Windows 常见显示缩放下的清晰度与可用空间。

本轮不建立截图基线或全组合视觉审批。人工检查只覆盖会影响当前发布判断的代表性组合。

## 12. 预期改动边界

实现预计只涉及：

- Main 窗口尺寸计算和外观广播；
- Preload 外观事件接口；
- 独立 AppearanceStore、设置页外观控件和保存分流；
- 主页面 DOM 的语义整理与统一图标；
- 主题 token、A/D 布局和响应式 CSS；
- 设置与 Electron smoke 的针对性测试；
- 必要的现状文档更新。

不借本轮进行无关的 Renderer 状态机重构、设置系统重写或其他产品架构扩展。
