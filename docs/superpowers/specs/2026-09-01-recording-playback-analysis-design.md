# 录音回放、同步分析与多 LLM 配置设计

## 状态与范围

状态：已完成对话设计，待维护者审核后进入实施计划。

本次功能让用户在应用本次运行期间保留最近五条训练录音，完成大模型分析后随播放进度查看对应片段的分析结果，并可切换已保存的大模型配置重新分析同一条录音。

本次不实现：

- 跨应用重启保存录音、逐字稿或分析结果；
- 历史录音数据库、文件导入或导出；
- 播放期间逐帧推理；
- 词级时间戳或波形展示；
- 同一录音的多份分析结果对比；
- 新的 ASR 模型、LLM 后端类型或模型下载机制。

## 用户体验

### 首次使用告知

用户第一次点击“开始录音”时，应用在申请麦克风权限前显示阻塞式说明。说明必须明确：

- 录音只保存在本次应用运行期间；
- 最多保留五条记录，第六条完成时自动释放最老记录；
- 关闭应用后释放全部录音资源；
- 录音用于本地回放、字幕同步和用户主动选择的大模型分析；
- 云端大模型只接收逐字稿、片段标识和片段时间信息，不接收原始录音。

用户确认后才继续录音。应用只持久化一个不包含用户内容的“已了解录音保留策略”布尔值，以后不重复弹窗。内置帮助页面长期展示相同说明。

### 运行期训练记录

应用按完成时间保存最多五条内存记录。每条记录包含：

- 唯一记录 ID、开始时间和录音时长；
- WAV `Blob` URL；
- 带时间范围的最终字幕片段；
- 本地规则分析和统计；
- 最近一次成功的大模型回放分析；
- 生成该结果时实际使用的 LLM 配置、provider 和 model 摘要。

字幕顶部增加“训练记录”选择框，条目显示录制时间和时长，例如 `14:32 · 02:18`。选择记录时同步切换播放器、字幕、统计和分析结果。新录音完成后自动选中。

第六条录音完成时删除最老记录、撤销其 `blob:` URL、取消其未完成分析并释放所有引用。“清除”只删除当前记录，随后选择剩余记录中时间最近的一条；本次不增加“全部清除”。关闭窗口时释放全部记录。

### 播放与同步显示

录音结束后显示原生音频播放器、LLM 模型下拉框和“重新分析”按钮。第一次大模型分析使用当前启用配置自动执行。分析期间允许播放，但播放不会触发推理。

播放、暂停、拖动和播放结束均通过同一时间轴选择逻辑定位当前片段。只有片段 ID 变化时才更新 DOM：

- 当前字幕高亮并滚动到可见区域；
- 右侧显示当前片段的大模型建议；
- 无建议时显示“该片段暂无特别建议”；
- 暂停时保持当前片段和结果。

空格键可切换播放和暂停，但仅在播放器存在、焦点不位于输入控件或按钮、没有打开弹窗且按键不是长按重复事件时生效。应用阻止该次空格的默认页面滚动。该快捷键不替代录音暂停/继续控制。

## 音频与时间轴

### 音频采集

现有 AudioCapture 产生的 16 kHz、单声道 Float32 PCM 分块继续送入 ASR，同时在 Renderer 中转为 Int16 分块供当前记录回放。转换完成后不额外保留 Float32 副本。

暂停录音时 AudioCapture 已停止接受分块，因此暂停时段不会进入保存音频。正常结束时 flush 尾部音频，然后用原生 `Blob` 组装 16-bit PCM WAV；不增加音频依赖。WAV 建立后释放 Int16 分块引用并只保留 `Blob` URL。

WAV 生成失败不影响逐字稿、本地分析或报告功能。应用给出明确提示并隐藏该记录的播放器。

### 片段时间轴

每条最终 ASR 文本对应一个片段：

```js
{
  id: "segment-3",
  text: "这里是最终识别文本",
  startMs: 8200,
  endMs: 11600,
  localAnalysis: {}
}
```

`endMs` 由产生该最终结果的 ASR 输入块结束帧除以 16 kHz 得到；即使 Renderer 已继续采集后续块，也不能把后续音频误计入当前片段。`startMs` 接续上一最终片段的 `endMs`。停止 ASR 时返回的尾部最终文本使用完整录音时长作为 `endMs`。时间范围必须单调、不重叠并限制在录音时长内。

当前 ASR 不提供词级时间戳，因此这是片段级近似同步。它用于切换整段字幕和建议，不承诺逐字对齐。

## 大模型回放分析

### 请求与结果

Renderer 通过新的受限 IPC 提交当前记录的片段数组以及选中的 LLM profile ID。Main 校验 profile ID、文本大小、片段数量、ID 唯一性和时间范围，从设置存储中读取完整配置快照，并向模型发送一次整段结构化分析请求。原始音频不经过 IPC，也不发送给大模型。

模型输入包含每个片段的 `id`、`text`、`startMs` 和 `endMs`。模型必须返回按片段 ID 关联的结构化建议；只需返回有建议的片段。

Main 严格校验模型结果：

- 只接受请求中存在的片段 ID；
- 拒绝重复片段 ID、错误结构和超长内容；
- 不通过文本相似度猜测或重新对齐；
- 成功响应附带实际使用的 profile ID、配置名称、provider 和 model 摘要。

模型超时、取消、网络失败或格式错误时，Renderer 不覆盖上一次成功结果。新分析开始后，旧的迟到响应不得覆盖新结果。

### 重新分析

回放区的模型下拉框仅显示各配置的 `model` 字段，内部值为唯一 profile ID。相同模型名允许出现同名选项，本次不追加 provider 或配置名称。

切换下拉框会更新全局当前 LLM 配置，但不会自动发起请求。用户点击“重新分析”后，当前记录使用所选配置重新分析。同一时刻最多运行一个回放分析任务；新任务取消旧任务，避免并发消耗和意外计费。成功后整体替换该记录原有的大模型回放分析。

本地填充词、犹豫词、笼统词等确定性分析不因重新分析而重算或改变。现有实时反馈和最终报告保留现有行为。

## 多组 LLM 配置

LLM 设置升级为具名 profile 列表：

```js
{
  schemaVersion: 2,
  activeProfileId: "profile-deepseek",
  profiles: [
    {
      id: "profile-deepseek",
      name: "DeepSeek 日常",
      provider: "deepseek",
      model: "deepseek-chat",
      apiKey: "..."
    }
  ]
}
```

各 profile 根据 provider 保存现有字段，包括 model、API Key、Ollama URL、base URL 和自定义模型兼容字段。设置页支持新建、重命名、复制、删除、编辑和设为当前配置。系统始终至少保留一个 profile。

旧 schema-v1 设置迁移为 profile 列表：当前 provider 对应的配置成为 active profile；其他 provider 中包含用户配置的数据也迁移为独立 profile，不能丢失已有密钥、URL 或模型字段。现有 future-schema 保存保护和原子 JSON 写入继续生效。

主训练窗口只能通过受限 IPC 获取 `{id, name, provider, model, active}` 摘要并按 ID 切换当前配置，不能读取 API Key、完整 endpoint 或其他凭据。设置窗口继续负责完整配置的编辑。

删除当前 profile 时选择剩余列表的第一项。分析请求使用启动时的配置快照；请求期间切换或编辑 profile 不改变在途请求，结果标记实际使用的配置。

## 资源边界

资源上限属于功能契约：

- 单条录音最长 20 分钟；达到上限时正常自动结束、flush 尾部音频并提示用户；
- 最多五条 Int16/WAV 录音，满额音频稳态内存约 192 MB；
- WAV 建立后立即释放 PCM 分块，删除或退出时撤销 URL；
- 只渲染当前选中记录的字幕和分析 DOM；
- 播放同步只在跨越片段边界时更新，不逐帧重绘；
- 同时最多一个回放 LLM 请求；
- LLM 请求设置字符数、片段数和输出长度上限；
- 继续使用现有十块 ASR 输入队列和过载失败保护；
- 不增加并行 ASR、后台音频 Worker、波形计算或多版本分析缓存。

如果资源边界阻止操作，应用必须给出用户可理解的提示，不能静默截断录音、逐字稿或模型结果。

## 错误与生命周期

- 新录音失败时不创建不完整的训练记录；已经存在的五条记录不受影响。
- 记录只有在音频停止和尾部 ASR 整理完成后才进入队列并参与五条淘汰。
- 删除记录、覆盖最老记录、清除全部应用状态和关闭窗口时，取消对应请求并释放音频资源。
- 切换记录不取消已经完成的结果；在途分析遵守全局单任务规则。
- LLM 分析不可用不阻止本地回放、本地规则分析、复制逐字稿或生成现有报告。
- 播放器操作异常只影响当前记录的回放，不应破坏其他记录。

## 实现边界

预计修改现有 Main、Preload、Renderer 和设置路径，并增加少量可单测的纯函数模块：

- `src/app.js`：记录队列、录音编排、播放器和同步 UI；
- `src/index.html` / `src/styles.css`：记录、播放器、模型选择和告知界面；
- 新的 Renderer 纯函数模块：PCM→WAV、记录队列和时间轴选择；
- `preload.js` / `main.js`：回放分析、脱敏 profile 列表和 profile 切换 IPC；
- `lib/ai-feedback.js` / `lib/prompts.js`：结构化回放分析请求与响应解析；
- `lib/llm-provider-config.js` / store：profile schema-v2、迁移和摘要；
- 内置帮助和必要的用户说明文档。

不引入数据库、前端框架、音频库或额外运行时依赖。

## 验证

自动化测试只覆盖能够发现材料回归的边界：

- PCM→WAV 文件头、采样率、长度和时长；
- 暂停时段不写入录音，20 分钟上限触发正常停止；
- 五条队列顺序、第六条淘汰、删除当前记录和 URL 释放；
- 片段时间单调性、边界查找、拖动和播放结束；
- 空格快捷键及输入控件、按钮、弹窗和重复按键排除；
- 只渲染当前记录，切换记录同步刷新播放器、字幕、统计和结果；
- 结构化 LLM 响应对未知/重复 ID、错误结构和超长输出的拒绝；
- 重新分析竞态、失败保留旧结果、清除后抑制迟到响应；
- schema-v1→v2 迁移、新建/复制/切换/删除 profile 和 future-schema 保护；
- 主页面摘要脱敏、受限 profile ID 和 IPC 输入大小；
- 首次告知阻止录音、确认状态持久化和帮助文案存在；
- Electron smoke 中使用 Fake ASR/LLM 验证录音结束后出现播放器与同步分析入口。

真实麦克风、真实外部 LLM 和长时间资源行为仍需要有针对性的手动验证；不把与本功能无关的模型、平台或发布资格验证加入门禁。

## 验收标准

1. 用户确认首次说明后，可以录音并在结束后回放；原始录音不离开 Renderer。
2. 应用运行期间可选择最近五条训练记录，第六条自动释放最老记录，退出后不留下录音文件。
3. 播放、暂停、空格键和拖动进度能稳定切换当前字幕及对应大模型建议，不在播放时推理。
4. 用户可以保存多组 LLM 配置，通过只显示模型名的下拉框选择配置并重新分析当前录音。
5. 新分析只有成功后才替换旧结果，取消、失败和迟到响应不会破坏已有结果。
6. 单条录音 20 分钟自动正常结束，五条记录、DOM 更新和 LLM 并发均遵守资源上限。
7. 本地规则分析、实时反馈、最终报告、模型管理和粘贴逐字稿路径没有材料回归。
