# 语速与停顿测量实施计划（第一阶段工具已实现）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 本计划不授权提交、推送或调用远程 AI。

**Goal:** 先验证整段语速与内部停顿的测量，再以独立版本接入报告和 AI；不把 VAD 间隔直接命名为卡顿。

**Architecture:** 第一阶段复用 `computeCommonAnalysis` 的基础测量与校验、现有只读 inspector 和固定配置探测脚本，只补新派生公式及定向验证，不修改生产 VAD、历史数据库和默认 AI 请求。先检查现有配置是否满足新用途；有具体误差或覆盖缺口时再开展配置对照。测量通过后，按第二阶段更新生产合同、版本、报告和诊断。

**Tech Stack:** Node.js、现有 sherpa-onnx-node / Silero VAD、Node test runner。

**Spec:** 用户在本聊天基本认可的整段速度/停顿方案；具体边界由下方设计基线限定。Canonical owner 为 `docs/architecture/data-model.md`、`docs/product/expression-problem-library.md` 和 `docs/product/training-flow.md`，本计划不替代它们。

## 设计基线与全局约束

- 首版覆盖平均速度、内部停顿特征及可复听区间；词句内的停顿位置是否合适、局部语速变化不属于首版。
- 现有其他九项指标不在本次删除范围。既有六项的产品展示取舍在接入时处理，不删除历史快照。
- 测量与评价分离：VAD 分段参数不等于卡顿判定阈值；不先设通用流畅度分数或速度好坏分界。
- 从首个语音区间起点到最后区间终点定义表达跨度 T；检测语音时长 S 为区间并集长度；内部间隔 P=T-S，次数为 N。所有时长先在 sample 坐标计算。
- 四项主统计：整体字符速率 C/T、检测语音字符速率 C/S、内部间隔占比 P/T、每表达分钟内部间隔次数 N/T；速率和频率换算到分钟。速度是字符代理量，不声称精确音节速度。
- 两种速率与间隔占比存在数学关联，不独立加权累加成评分。
- 字符数 C 使用现有 Unicode 文字与数字口径。无完整、同一音频覆盖的转写时，两种字符速率不可用；有效声学测量可独立保留。
- 无有效语音跨度、分母为零、VAD 失败、音频缺损分别传播不可用状态；不可用不补零。有效单语音区间可有零内部间隔。
- 每个正内部间隔保留 sample 边界与时长；不把强制切段形成的相邻边界视为停顿。不用估计转写时间将间隔绑定到具体词句。
- 首尾非语音单独记录为核查信息，不计入内部间隔。VAD 非语音不保证是物理静音。
- 工作区已有未提交改动必须保留；不提交、不推送。只读核验工具 `scripts/inspect-speech-evidence.js` 继续只读，不增加模型推理副作用。

## 路线取舍

采用“盘点已有证据与资产 → 补派生公式和必要测试 → 复核新用途 → 按误差决定是否调参 → 版本化生产接入”。直接恢复六项 AI 输入无法解决解释边界；立即引入词级对齐会扩大首版范围。现有配置有有限人工复核基础，不因仍带未校准标记就默认必须更换参数；也不把历史验收当作新用途已经达标。

## 已核对的复用基础与限制

- `lib/common-analysis.js` 已计算 S、P、N 和 C/S，并校验音频覆盖、ASR 完整性、VAD 来源和可用性。对合法、完整、同源区间，T=S+P；新增独立公式主要是 C/T、P/T、N/T。旧 C/完整录音时长不等于 C/T。
- `test/common-analysis.test.js` 已覆盖准确数值、两类分母、首尾静音分离、零语音和异常降级；只补新分母及派生公式特有边界。VAD 引擎负责区间规范化，Common 对重叠/乱序/非法边界拒绝，不另建一套冲突的自动修复口径。
- `scripts/inspect-speech-evidence.js` 和对应测试已有只读快照选择、WAV hash 校验、语音区间、内部 gap、首尾非语音导出及保存汇总重算核对。它复用同一计算器，只证明保存一致性，不是独立检测准确性证据。
- `docs/milestones/m2-speech-evidence-and-ai-diagnosis.md` 的 H-01 记录过短/长停顿的有限人工复核；第 104 行记录两条 WAV hash 与区间/汇总一致性核验。保留该证据，不重新表述为“此前从未人工复核”，也不外推代表性准确率或流畅度效果。
- `scripts/validate-speech-evidence.js` 已有固定配置下的中文朗读、数字静音、150 ms/1.5 s 构造间隔、低幅合成噪声及资源测量。可复用探测结构；它要求外部语料 manifest 和至少十二条记录，现阶段未核验该外部语料仍可用。现有 Silero 缓存已核对文件大小/hash 与 registry 一致，本轮不需要下载或重新推理。
- 仓库三条现有语音 WAV 已确认存在；未据此声称包含自然表达各类卡顿或已有完整人工边界标签。未找到系统多配置对照/完整边界标注证据。

## 第二阶段：本地报告与后续 AI 对照

有限复听支持先将已检测区间接入本地复盘。指标、快照和交互分别以 Data Model §5.3 和 Training Flow §7.2 为准。原 VAD 参数继续使用，阈值与判断能力留待对照证据。

1. **版本与兼容。** 更新 `lib/common-analysis.js`、`lib/session-analysis.js`、`lib/session-comparison.js` 及相关测试；为改变分母的新速率使用新指标身份，保留旧定义的历史解释路径。新旧定义或 VAD 参数不兼容时不计算改善差值。不要只替换一个全局版本常量，使旧结果失去解释路径。
2. **证据与界面。** V2 报告展示九项观测，绑定同一 Session/revision/source，支持查看命中用词与回放内部间隔。缺失时局部降级，旧报告保留原展示。
3. **AI 输入与规则。** 正式主诊断沿用原三项指标名单。后续对照独立验证新增数据的价值，再决定是否调整发送字段或判断规则。
4. **质量对照。** 已完成首轮固定实录对照并保留请求与返回，结果见 [Current §17](../../architecture/current.md#v2-用词与停顿的实录对照)。逐处判断下一轮先验证转写对齐及自然停顿对照，再检查能否复现人工判断。
5. **生产放行。** 相关 Common、Context、Diagnosis、Comparison 和 Report 测试通过后，走实际录音→报告→证据回放→重启→新旧报告混读；依变更影响扩展验证。真实测量与 AI 内容分别验收，不用结构测试代替两者。同步 Data Model、Current 与 Development 的各自 owner，实施事实确认后移除一次性计划。
