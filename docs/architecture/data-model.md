# Training Data Model

> **Status:** Canonical model — M1 facts, M2 result contracts and M3 comparison; remaining target entities are identified separately
> **Date:** 2026-09-19
> **Scope:** logical model, M1 persistence decisions, M2 V1 result contracts and M3 read-only comparison; this is not a complete future SQL schema.

## 1. Purpose

`TrainingSession` is the durable centre of the product. Audio capture, ASR, deterministic metrics, AI analysis, comparison, and conversation are processors or views of a session; none of them owns the session itself.

The model separates:

- **facts:** what the user did and what the application actually received;
- **derived results:** interpretations that depend on an algorithm, prompt, provider, or model and can be recomputed.

This separation is required by R-P01–R-P06 and NFR-02/NFR-04.

## 2. Aggregate overview

```text
TrainingSession
├── Artifact[]
│   └── audio
├── Transcript
│   └── TranscriptSegment[]
├── SourceSnapshot
│   ├── ASR model/version
│   └── training context
├── SpeechEvidenceRun[]       M2, neural VAD, versioned
├── MetricRun[]               derived, versioned
├── AIAnalysis[]              derived, versioned
├── FrameworkAnalysis[]       M4, derived, versioned
├── Comparison[]              M3
└── Conversation[]            deferred; M3 candidate
    └── Message[]
```

M1 implements the foundation represented by `TrainingSession`, `Artifact`, `Transcript`, `TranscriptSegment`, `SourceSnapshot`, and storage of already-produced derived snapshots. M2 V1 在这一基础上增加 §5.2–§5.4 的结果契约；Comparison、Framework Analysis、Conversation 等仍是后续所有权边界。每次训练或重练 attempt（Free 或 Structured）均对应独立的 `TrainingSession`，不建立平行的 attempt aggregate。问题重练的来源问题、来源 Session 和范围关联在后续里程碑细化，不提前扩张 M1 schema。

## 3. Fact and derived-data rules

### 3.1 Immutable facts

After a session reaches `completed`, these fields are append-only or immutable:

- session identity, source, start/completion time, and duration;
- selected `trainingMode`, `framework`, and training-prompt snapshot as they were when the session started;
- persisted audio bytes and their integrity metadata;
- final transcript text and stable transcript segments;
- the ASR model identity/version used for the recording;
- explicit data-quality events such as audio overrun or missing timing.

Correcting corrupt metadata creates a repair event or a new revision; it does not silently rewrite the original fact.

### 3.2 Versioned derived results

The following may be regenerated by an explicit user or system action and therefore never overwrite their provenance:

- deterministic expression metrics;
- AI diagnosis, suggestions, and rewrites;
- radar values;
- framework assessment;
- comparisons and trend calculations;
- report snapshots and their projected radar values.

Each derived result records at least `inputRevision`, `definitionVersion`, `createdAt`, `status`, and the evidence references it used. AI results also record provider/model/prompt-schema identities without credentials. A Report shown to a user is a stable generation-time snapshot of the result versions it composes; algorithm or prompt upgrades do not silently regenerate or alter a historical Report.

`trainingMode` is an immutable fact about how the user trained. An analysis kind or framework used for re-analysis is derived metadata. Creating a new analysis must never rewrite `trainingMode`, `framework`, `trainingPrompt`, audio, transcript, or transcript timing.

At the logical boundary, every derived analysis identifies its own `analysisMode` (`common`, `framework`, or `coaching`), `framework` when applicable, and `analyzerVersion`. These fields belong to the analysis record, not to `TrainingSession`; therefore a Free session can acquire an explicit PREP re-analysis while remaining a Free session.

## 4. M1 logical entities

Field names in this M1 section are logical domain names. Implemented SQL/storage details are in [Current §10](current.md#10-m1-training-storage-foundation); M2 V1 result contracts are in §5.2–§5.4, while later entity schemas remain unselected.

### 4.1 TrainingSession

| Field | Type/shape | Rule |
|---|---|---|
| `id` | opaque stable ID | Generated once; never reused |
| `schemaVersion` | integer | Required for supported forward migration |
| `source` | `microphone` | M1 and the target product accept only microphone training |
| `status` | `recording` \| `finalizing` \| `completed` \| `incomplete` \| `corrupt` | Only `completed` is presented as a healthy completed record |
| `createdAt` | UTC instant | Wall-clock display/sorting value |
| `completedAt` | UTC instant or null | Set only when finalization succeeds |
| `durationMs` | integer | Completed microphone-session duration |
| `trainingMode` | `free` \| `structured` | Defaults to `free`; M1 creates only `free` sessions |
| `framework` | stable framework ID or null | Null for `free`; required for `structured`; initial IDs are `prep`, `star`, and `pyramid` |
| `frameworkDefinitionVersion` | version or null | Null for `free`; records the selected definition for a Structured session |
| `trainingPrompt` | `TrainingPromptSnapshot` or null | User-visible topic/scenario supplied before training; M1 always writes null because topic/scenario entry begins in M4 |
| `title` | text or null | User or application label; not evidence; M1 uses null and adds no title-editing feature |
| `dataQuality` | flags/event references | Examples: timing unavailable, audio overrun, artifact missing |
| `timing` | versioned snapshot or null | Recorded canonical audio count/rate, separately observed ASR-accepted count and evidence capabilities; null for legacy records without this snapshot, not inferred from transcript estimates |

`status` is a product-visible integrity state, not only an internal database flag.

Training Workspace 的 Preparing / Recording / Processing，以及 Report / Comparison 的可用性是展示或任务结果状态，不直接映射为 Session 持久化状态。报告分析超时或局部失败不能把已完成、已保存的 Session 改成 incomplete/corrupt；保存失败也不能被 Report 状态掩盖。重试基于同一 Session 追加版本化结果，不重复创建训练事实。

`TrainingPromptSnapshot` 为可空的版本化上下文。当前编辑产生 v2，分别保存主题和场景：

| Field | Type/shape | Rule |
|---|---|---|
| `schemaVersion` | `2` | 训练上下文载荷版本，不等于 SQLite/Session schema |
| `topic` | `{source, text}` or null | 本次讲什么；独立保留主题来源与完整文本 |
| `scenario` | `{source, text}` or null | 向谁、在什么情况下表达；独立保留场景来源与完整文本 |

每一项的 `source` 为 `user` / `bank` / `generated`；M4 首版产生 user/bank，generated 保留兼容。每项文本独立限制为 2000 个字符并保留原始非空内容；编辑时清空或仅有空白表示该项为 null，两项皆空时整个 `trainingPrompt = null`。不接受未知版本、多余字段或无效来源。

兼容早期未带版本的 `{source, kind, text}`，其中 kind 为 topic/scenario。读取与重分析保留原形，不改写旧记录；准备界面将它映射到对应胶囊，修改任一主题/场景后使用 v2。准备偏好只在实际采用该上下文创建录音记录后更新，独立于 Session 删除；偏好恢复/写入失败不使录音事实失效，也不阻止无题目开始。

The consistency rules are:

```text
trainingMode = free       -> framework = null and frameworkDefinitionVersion = null
trainingMode = structured -> framework != null and frameworkDefinitionVersion != null
trainingPrompt             -> independent of trainingMode and framework
```

产品中的 Training Context（主题/场景）对应可空的 `trainingPrompt`，Practice Focus 是本轮练习目标；来自 Finding 时通过 §6 的来源关系识别。二者正交，Finding 标题不能写入 `trainingPrompt` 代替主题，空主题也不妨碍保留练习目标。`trainingMode`/framework、分析指令继续保持各自独立语义；不新增平行的题目或 Focus 事实副本。

上次 Framework / Topic / Scenario 配置属于可复用的准备偏好，恢复行为由 [Training Flow §3.1](../product/training-flow.md#31-默认状态) 定义；它不是当前 Session 的事实引用。Practice Focus 由 §6 的 Finding / 练习链来源识别，不进入普通上次配置。新 Session 开始时复制实际采用的上下文快照，之后偏好或来源变化不得改写旧事实。

The setup values may change while the UI is preparing a session. Once recording begins, the session snapshots and freezes `trainingMode`, `framework`, `frameworkDefinitionVersion`, and `trainingPrompt`. M1 exposes no topic/scenario input, so every M1 session uses `trainingPrompt = null`; the nullable field is reserved for the accepted M4 flow rather than produced early.

### 4.2 Artifact

| Field | Type/shape | Rule |
|---|---|---|
| `id` | stable ID | Scoped to one session |
| `sessionId` | ID | Required parent |
| `kind` | `audio` initially | Extensible only when a real artifact appears |
| `state` | `staging` \| `available` \| `missing` \| `corrupt` \| `deleted` | Never infer availability from a non-empty path |
| `relativePath` | relative path or null | Resolved only inside the application data root; no absolute path in UI contracts |
| `mediaType` | text | Example: `audio/wav` |
| `byteLength` | integer | Checked on read when practical |
| `sha256` | digest | Integrity and duplicate/corruption diagnosis, not user identity |
| `sampleRateHz` | integer or null | Recorded output format |
| `channels` | integer or null | `1` for current recordings |
| `durationMs` | integer or null | Artifact duration when known; derived from validated sample count/rate and rounded to integer milliseconds |
| `createdAt` | UTC instant or null | Actual recorded artifact creation time; null when not recorded, never inferred from filesystem timestamps or session start time |

Audio bytes are stored as files under the application data directory. The database stores metadata and relative references. Blob URLs are runtime handles and are never persisted.

M1 的单音频不要求为上述逻辑字段重复增加 SQL 列：固定格式且已校验的 WAV 可从音频元数据派生时长，未知值返回 null。独立音频生成时间未采集时按未知处理，不为补字段伪造历史时间。字段的当前投影与尚未接入项统一见 [Current §10](current.md#10-m1-training-storage-foundation)。

### 4.3 Transcript

| Field | Type/shape | Rule |
|---|---|---|
| `id` | stable ID | One canonical completed transcript per M1 session |
| `sessionId` | ID | Required parent |
| `source` | `local-asr` | Canonical transcript comes from the selected local ASR path |
| `text` | text | Canonical completed text |
| `revision` | integer | Starts at 1; future user correction creates a new revision rather than rewriting provenance |
| `createdAt` | UTC instant | Creation time |

M1 does not persist every interim ASR partial. That event log has no accepted product use and would increase storage and migration cost.

### 4.4 TranscriptSegment

| Field | Type/shape | Rule |
|---|---|---|
| `id` | stable ID | Evidence target for reports and playback |
| `transcriptId` | ID | Required parent |
| `sequence` | non-negative integer | Strictly ordered and unique within a transcript revision |
| `text` | text | Segment text |
| `startSample` / `endSample` | integer or null | Absolute offsets in the canonical 16 kHz session timeline when known |
| `startMs` / `endMs` | number or null | Derived display convenience; never presented as precise when the source is approximate |
| `timingSource` | enum | Sources are defined only by [Speech Contract §6.2](speech-contract.md#62-timing-sources); unsupported sources must not be fabricated |
| `timingVersion` | version or null | Algorithm version for estimated intervals; unknown historical versions remain null |
| `confidence` | number or null | Only stored when the provider defines it |

Timing fields are nullable as a group. Paraformer-like providers without useful timestamps must produce `timingSource = unavailable` or a clearly labelled estimate; they must not invent exact token timing.

### 4.5 SourceSnapshot

M1 stores the identities required to interpret the record later:

| Group | Required values |
|---|---|
| Application | application version and session schema version |
| ASR | provider family, model ID/version, and timing capability for microphone sessions |
| Rules/metrics | ruleset or analyzer version for any persisted current statistics |
| AI result | profile/provider/model identifier, LLM template/schema version, generation time, and the analysis-instruction snapshot/revision when available |
| Training context | selected training mode, framework/definition version, and optional `TrainingPromptSnapshot`; M1 records the prompt as null |

`TrainingPromptSnapshot` and analysis instructions are different concepts. The former is the topic/scenario shown before recording. Existing `custom-prompt.json` values (`goals`, `customRules`, `styleRef`, and normalized `customWords`) are **analysis instructions** consumed by local rules or LLM requests. When an existing derived result is persisted, M1 stores the normalized instruction snapshot or a stable revision/hash captured for that result when available; if the current implementation did not capture it at generation time, provenance is explicitly `unknown` rather than reconstructed from later settings.

Secrets, complete settings snapshots, endpoints containing credentials, and API keys are excluded. Analysis-instruction snapshots contain only the user-authored fields actually supplied to the relevant analyser and remain subject to the remote-AI disclosure boundary.

## 5. Later derived entities

下表定义派生实体的所有权与不变量；M2 V1 的具体结果契约见 §5.2–§5.4，后续里程碑仍不提前冻结物理表。

| Entity | Milestone | Frozen boundary |
|---|---|---|
| `SpeechEvidenceRun` | M2 | Belongs to one audio artifact/session; records neural-VAD engine/model/threshold versions and derived intervals without replacing transcript facts |
| `MetricRun` | M2 | Belongs to a session/transcript revision; immutable Common metric result with analyzer definition version and evidence references; the same measurable fact uses one definition across training modes |
| `AIAnalysis` | M2 | Default derived result for each analyzable session; consumes a versioned `AnalysisContext` of facts, speech evidence and deterministic metrics, then stores a schema- and evidence-reference-validated interpretation with provider/model/prompt versions, status, and explicit unavailable/failed states |
| `Finding` | M2 | First-class, immutable diagnostic object in an analysis result: controlled category, observation, interpretation, recommendation, `evidenceRefs`, and provenance. It is the Report diagnosis single source of truth; insufficient evidence produces no fabricated Finding |
| `ReportSnapshot` | M2 | Composes exact MetricRun/AIAnalysis/Finding/evidence versions and availability into one stable Report; internally retains `evidenceVersion`, `metricsVersion`, `analysisVersion`, and `radarVersion` when applicable. Radar values are projections retained with their source/mapping/version, never a second analyzer |
| `Comparison` | M3 | References explicit baseline and target sessions plus the metric/analysis versions used |
| `Conversation` / `Message` | Deferred；M3 候选 | 未来优先引用来源 Session / Report、Finding 所属分析版本及 Evidence；声明使用的上下文，messages 不修改 Session facts；具体 schema 随 B-17 / D-05 重开 |
| `FrameworkAnalysis` | M4 | Belongs to a session/transcript revision and records `framework`, `analyzerVersion`, status, findings, and evidence references; it never changes the session's training context |

No SQL columns for these later entities are frozen in M0.

### 5.1 Speech Evidence V1

Speech Evidence 是录音、VAD / ASR 输出及确定性计算的统一证据边界，供 Report、Metric engine、AI、Finding 的证据关联、Comparison 与针对性练习反馈复用。它描述观察或计算结果，不直接评价表达好坏或产生主观分数；模型观察仍可能有误差，必须保留来源与质量局限。

以下五部分是统一证据的概念骨架，不是一张新的持久化表；沿用现有 Session / Artifact / Transcript / Run 关系。M2 V1 的具体引用与结果形状见 §5.2，不把该切片推广成全部未来 Evidence 的 Schema。

| 部分 | 内容与既有归属 | 边界 |
|---|---|---|
| `audio` | Artifact 与 Session timing 中的时长、采样率、sample 数、已接受范围及最终 cursor | 时间定义复用 [Speech Contract §6](speech-contract.md#6-time-and-timestamp-rules)，不另建时间轴 |
| `speech` | `SpeechEvidenceRun` 产生的 canonical speech segments | 持久化必要说话区间，不同时永久保存可由其推导的另一套 non-speech segments |
| `transcript` | 既有 Transcript / TranscriptSegment、真实可用的可选 timing | 不复制一套主转写；未知 timing 不补造，估计区间仍按 §4.4 标识来源，不冒充 token 对齐 |
| `derived` | 基于基础证据的确定性计算快照，如说话/静音时长、停顿次数/时长、最长停顿、语速 | 复用 `MetricRun` 的计算职责与版本化结果边界，不新建一套同口径计算或评分层；最终集合、单位、分母及缺损规则尚未完全冻结 |
| `quality / provenance` | 证据可用性、缺损、能力限制、来源与版本 | 属于持久化契约，不只是运行日志；按下述分区规则记录 |

non-speech 的推导须以有效音频覆盖和 VAD 结果为依据，缺口、丢音频或未知区间不能当成静音。VAD 识别语音/非语音；停顿和长停顿阈值属于上层确定性派生规则，沿用 §6 的 Metric 职责及 leading/trailing silence 边界，不写死在 VAD 模型内部。“最长停顿时长”是客观计算，“停顿过长”是解释；概念中的 Derived 不把既有 deterministic Metric 改成主观评分，也不撤销 R-C04 已有本地统计。

#### 持久化与历史快照

每个 Session 关联并持久化版本化 Evidence Snapshot：保存必要 Source Evidence 和当次 Derived 结果，并能从 Derived 追溯其输入证据及规则版本。Source 是当次观察/模型输出的依据，Derived 是依赖它的计算快照，不是两套平级原始事实。这里的 Snapshot 复用上表既有实体/结果的归属，不新增平行 aggregate，也不把“一份快照”解释成永久禁止同一 Session 有多个分析 Run。

历史读取沿用 §3.2 的 Report 稳定性和 §10 的 Comparison 规则：默认使用当时证据与计算快照，不因 VAD、ASR 或规则升级在打开时自动重跑或改写。快照的保存不保证跨版本天然可比；本切片的 Partial 重试追加规则见 §5.2，完整历史报告的主动重新分析和快照选择仍需随相应能力细化。

VAD 每帧概率、ASR 内部 tensor/模型状态、中间 PCM buffer、debug trace、大量性能 telemetry 和完整 AI prompt/debug trace 不作为 M2 产品级 Evidence 常规持久化内容。这不取消 [Speech Contract §10](speech-contract.md#10-observability-and-acceptance-evidence) 的必要有界诊断或 §4.5 已要求的分析指令/来源快照；原始录音的保留、删除与隐私继续按 §9 及既有存储规则执行。

#### 版本与来源

| 维度 | 已确认规则 |
|---|---|
| `schemaVersion` | Evidence payload 使用整数版本；V1 为 `1`，不等于 Session 或 SQLite schema 版本 |
| producer | 按 ASR / VAD 分区保留生产者及版本，复用既有模型标识和来源快照；模型、阈值、规范化配置仍须满足 §6 的可追溯要求 |
| `derivationVersion` | 标识当次 Derived 使用的一套派生规则；与既有结果的 `definitionVersion` / analyzer 元数据对齐，不为每个数值再建独立版本体系；具体字段映射待实现契约细化 |

版本与来源按分区记录，不把每个值包装成重复携带模型、版本、时间与置信度的大对象；§3.2 既有结果 provenance 义务仍适用。

#### 分区 quality

quality 表示证据本身的可用性、缺损及局限，不是用户表达质量，也不保证识别正确率。按 `audio / timing / vad / asr` 分区记录状态与原因：

| 状态 | 含义 |
|---|---|
| `ok` | 该分区证据正常可用 |
| `degraded` | 仍有可用信息，但有缺损、精度或能力限制 |
| `unavailable` | 该类证据不可用 |

不建立 0～100 的 Evidence quality score，也不以单一全局 good/bad 替代分区状态。没有 token timestamp 反映 timing 能力限制，不自动判定 ASR 文本或其他证据失效；VAD 与 ASR 失败可分别表达。分区 quality 不替代 Run 执行状态、Session 完整性状态或 Report 可用性；完整 reason 枚举、能力不支持与运行异常映射、缺失值表示及依赖传播仍待细化，不把示例直接当成最终 Schema。

### 5.2 M2 结果快照与证据引用

M2 V1 复用现有 SQLite results 存储版本化 JSON payload，不新增 Evidence aggregate 或平行事实表。每条结果沿用 §3.2 的 `id`、`sessionId`、`inputRevision`、`definitionVersion`、`analyzerVersion`、`createdAt`、执行 `status` 和来源信息；同一次报告通过精确结果 ID 绑定输入，不以“某类最新结果”在读取时重新拼装。下列 M2 kinds 仅由 Main 的 Session analysis 服务生成，Renderer 不能直接提交伪造的 M2 结果。

| Result kind | Payload 与输入绑定 | 版本 / 边界 |
|---|---|---|
| `speech-evidence` | Source VAD 快照：`audio` sample 数/采样率、`segments`、`capabilities`、`quality.vad`、`provenance` 和 source 执行 `status` | `schemaVersion = 1`；来源使用 `engine` / `engineVersion` / `modelId` / `modelVersion` / `modelSha256` / `thresholdVersion` / `thresholds` / `normalizationVersion`。未运行或失败时未知值为空，不由当前设置补造 |
| `common-analysis` | §5.3 的确定性测量与逐项状态，`speechEvidenceRunId` 指向当次 Source result，保留其版本和 quality | `schemaVersion = 1`，`definitionVersion = common-metrics-v1`；`inputRevision` 与当前输入 transcript 一致 |
| `diagnosis` | §5.4 的结构化摘要/Finding 或局部不可用原因；`speechEvidenceRunId`、`metricRunId` 绑定实际输入 | `schemaVersion = 1`；实际提示版本由 provenance.promptVersion 与报告 analysisVersion 记录，`example` 可选扩展使用 `structured-diagnosis-v5`；provider/model/profile 与分析指令快照保留在该 result 来源中 |
| `report-snapshot` | `evidenceRunId`、`metricRunId`、`analysisRunId` 引用本次组合的三个结果；保存 `availability` 和各版本 | `schemaVersion = 1`；雷达未校准时保存 `radar.status = unavailable`、`reason = not-calibrated`、`version = null`，没有数值投影 |

Source 的区间以 canonical 16 kHz 音频为基准，使用 `[startSample, endSample)`、Run 内的稳定 `speech-N` ID；裁剪到真实 sample 数、排序并合并重叠或相接区间，保留实际间隔。不持久化第二套 non-speech intervals，也不声称 lexical/token timing。结果封装层使用 `completed / failed / unavailable`；source payload 仍可独立记录 `cancelled`，不把未完成推理当成整段静音。

Transcript evidence 继续使用既有稳定 segment ID；payload 内的音频证据使用 `audio`，VAD 使用当次 `speech-N`，Metric 引用使用 `metric:<metric-id>`。这些局部引用由对应 Session、`inputRevision` 和精确 Source/Metric result ID 限定；它们不是跨 Run 全局 ID。外层 result 的 `evidenceRefs` 仍保存已有 transcript segment 引用，payload 中的测量/Finding 引用按上述所属运行解析。未知引用或旧 revision 不得自动对应到新结果。

新训练事实保存后可生成一次报告；被动 History 读取只读取已保存快照。对 Partial 结果的明确重试追加新的 Source、Metric、Diagnosis 和 Report 结果，保留旧快照，不改写事实。完整历史报告的主动重新分析与快照选择 UI 不由此扩展；升级不触发自动重跑。

### 5.3 Common Metric V1 定义

`common-metrics-v1` 是对保存事实的纯确定性测量。文字计数为 Unicode 文字与数字字符，排除空白、标点和其他符号；词表命中沿用当次本地统计及自定义词表快照，不以今日词表重新扫描历史。实现入口为 [Common Analysis](../../lib/common-analysis.js)，共享字符口径见 [text statistics](../../shared/text-statistics.js)。

Common result 的 `localStatsSnapshot` 保存本次采用的词项计数输入，未知时为 null；可知的自定义词表保存在同一 result 的 `provenance.promptSnapshot.customWords`。新训练首次完成事实保存时可计算该输入；Partial 重试优先复用同一 transcript revision 的已有 Common 输入或旧 `metrics` 统计，不因之后修改词表而改变它。早期 M2 结果只有词表快照时可按该快照恢复；历史两类证据均缺失时，依赖词项的指标为 unavailable，其余测量和 AI 诊断仍可运行。AI 的训练目标/分析指令可在显式重试时更新，不改变已保存词项统计。

| Metric ID | 单位 / 分母 | 输入与含义 |
|---|---|---|
| `text-character-count` | `characters` | 已保存 transcript 的文字与数字字符数；不是分词后的词数 |
| `audio-duration-ms` | `ms` | 有效 Artifact 的 sample 数 / 16；历史未知 sample 数时使用已校验 WAV 的时长，不使用墙钟或估计 transcript 时间 |
| `filler-count` / `hedge-count` / `vague-word-count` | `occurrences` | 当次本地词表的填充词、犹豫词、笼统词命中次数，不等于主观问题次数 |
| `text-rate-per-recorded-minute` | `characters/recorded-minute` | 文字与数字字符数 / 已保存音频分钟数，分母含静音 |
| `filler-rate-per-recorded-minute` | `occurrences/recorded-minute` | 填充词命中次数 / 同一录音分钟数 |
| `hedge-character-percent` | `percent` | 犹豫词命中字符数 / transcript 字符数 × 100，四舍五入为整数 |
| `non-filler-hedge-character-percent` | `percent` | 排除填充词与犹豫词命中字符后的剩余字符占比；同一分词位置重叠命中只扣一次，四舍五入为整数；不是表达质量分 |
| `speech-duration-ms` | `ms` | canonical VAD speech 区间长度总和 / 16，名称保留“VAD 检测” |
| `non-speech-duration-ms` | `ms` | 有效覆盖音频时长减去 VAD 检测语音时长，包含 leading/trailing non-speech |
| `between-speech-gap-count` | `occurrences` | 相邻两个检测语音区间之间的正间隔次数，排除首尾非语音 |
| `between-speech-gap-total-ms` / `between-speech-gap-max-ms` | `ms` | 上述内部间隔的总时长 / 最长时长，不含额外“长停顿”阈值 |
| `text-rate-per-speech-minute` | `characters/speech-minute` | transcript 字符数 / VAD 检测语音分钟数；只是总量比率，不是逐字对齐语速 |

每个 metric 保存 `available / unavailable`、`value`、`unit`、`reason` 和实际 `evidenceRefs`；不可用值为 `null`，不是零。分母为零时相应速率/占比不可用。没有 speech detections 的完整有效 VAD run 可记录零检测语音和零内部间隔，按检测语音分钟的速率仍不可用。

依赖缺损按项传播：无效 transcript/本地统计阻断相应文字统计；音频缺失、范围不匹配、`audio-overrun` 或 `audio-discontinuity` 阻断依赖完整覆盖的 VAD 与混合速率；同时检查 Session 质量标记与 timing quality events。ASR 失败或接受 sample 少于采集 sample 时阻断需要完整转写的音频速率，仍保留已有文字观察。单纯缺少 token timestamp 不使所有文字或总量指标失效。

VAD 是模型观察。当前 `vad-thresholds-uncalibrated` 作为降级原因随 Source 和 Metric 保留；只要音频覆盖完整、区间有效，可显示检测总量与间隔，但不得据此宣称检测了所有短停顿。短静音可能被合并、边界可能带模型 padding；“间隔时长”不能直接解释为“停顿过长”“不流利”或数值评分。D-07 的 M2 有限人工复核已通过，但不据此移除未校准标记；扩大统计校准按 Backlog B-24 重开；雷达量程与完整校准延后至 Backlog B-20，M2 保持上述未校准快照。

### 5.4 Structured Diagnosis V1

AI 输入是有界的 `AnalysisContext`：同一 Session/revision 的 transcript、可用音频时间事实、Speech Evidence、Common Metrics、分区 quality 和已捕获的分析指令；不附带原始录音、完整设置或凭据。`allowedEvidenceRefs` 由上述真实输入生成；超过输入上限或 revision 不匹配时显式不可用，不静默截断后假装证据完整。可执行边界见 [Analysis Context](../../lib/analysis-context.js)。

输出严格为 `schemaVersion = 1`、`summary`、`findings`。每个 Finding 包含唯一 `id`、受控 `category`、`observation`、`interpretation`、`recommendation`、至少一个实际 `evidenceRefs`，以及可选 `example`；通用与框架 Finding 使用相同字段语义。类别的唯一产品定义见 [Training Flow §7.1](../product/training-flow.md#71-完整分析与训练重点分层)。未知字段、未知引用、重复 ID 或无效类型均拒绝；没有充分证据时 Findings 可以为空。解析与边界上限见 [Structured Diagnosis](../../lib/structured-diagnosis.js)。

`structured-diagnosis-v6` 及后续版本的新请求必须返回 `assessment:{status,reason,categories,frameworkAssessable,evidenceRefs}`；保留 schemaVersion=1 的扩展兼容，历史缺失该字段不补算、不改写。status 为 `analyzable / limited / insufficient`，reason 为 1～800 字符，categories 为不重复的受控类别，frameworkAssessable 为布尔值；evidenceRefs 最多20个、不重复且只引用当前转写，有可评价内容时至少一个。Finding 只能属于声明可评价的类别；frameworkAssessable=false 时不产生专项结果。insufficient 必须没有可评价类别、专项结果、Finding。材料充分程度独立于请求/报告技术可用性：成功的不足判定仍是 completed Diagnosis，不改成网络/模型失败，不丢弃本地指标。

`recommendation` 是具体、可执行的下一轮表达练习建议，仍使用既有字段，不新增 tip。`example` 是一种建议表达方式，不是用户原文或 Evidence，不得虚构现实中的负责人、时间、经历或事实。字段可缺失或为 null；提供字符串时必须为非空文本且不超过1600字符。旧结果缺失/null时正常读取并省略表达参考区，不复制 recommendation、不填固定示例、不自动重分析或改写历史。扩展沿用 schemaVersion=1 的可选字段兼容及现有提示/报告版本机制，不改变 Session/SQLite schema，其他字段的类型、长度和引用校验保持严格。

新诊断中的非空参考还须提供 `exampleEvidenceRefs`（1～20个不重复的当前转写 ID）。首批采用保守整理：只选择/重排由标点分隔的完整原文分句，不允许分句内部增删文字，防止通过子串匹配删掉否定词。缺少来源、出现新的分句/数字/常见日历数量表达或参考中混入补充占位时，只将该参考规范为 null 和空引用，保留有效 Finding；字段类型或长度非法仍拒绝。所需补充信息放在建议中作为问题或占位提示，不能拼成已经发生的事实/承诺。引用和字面检查不构成语义真实性证明，跨句因果、条件依赖或省略后含义改变仍需内容验收；本批不将自由改写视为已验证能力。

AI 解释已测事实，不重算时长、频次、比例或给出雷达/总分；不推断未提供的精确词时刻、声学特征或情绪质量。输出没有 severity/priority 必填字段、重练执行控制或自动范围选择字段。启用与失败恢复按 Training Flow §6.1/§7.6，结构化失败不改写 Source、Metric 或训练事实。

主诊断 `structured-diagnosis-v9` 沿用上述输出字段，在本地 result 的现有 provenance 中增加可选 `problemLibraryVersion`，记录实际使用的问题库版本（首次接入为 `expression-problem-library-v0.3`，本轮质量候选为 v0.4）；它不是 AI 响应字段，也不混入用户分析指令快照。旧来源缺失该字段时保持缺失，不用当前库版本补写历史；`promptVersion` 和 ReportSnapshot.analysisVersion 记录本次提示词版本。不新增 SQLite／Session schema，原有四类、Finding ID 和历史读取规则不变。

历史 v8/v9 曾在所选框架的平铺响应缺失 `frameworkRecommendation` 时补 null，并保存 `responseNormalization:{code,field,value,rawResponse}` 回执。v10 不再生成推荐字段、补 null 或写新回执；生产新响应包含该字段（包括 null）时按未知字段拒绝。旧快照及历史回执原样保留，不重算、不迁移；读取时仍验证旧回执的四字段、固定 code=`selected-framework-recommendation-null`、field=`frameworkRecommendation`、value=null 和 1～64000 字符的 rawResponse，避免将既有结果误判为损坏。

## 6. Analysis and retraining invariants

- Every analyzable session has a Common Analysis view. Free sessions may receive general organisation and structure findings without being judged against PREP, STAR, or Pyramid slots.
- Neural VAD creates independent `SpeechEvidenceRun` records. Its results may support Common metrics or AI context, but never overwrite audio, ASR transcript, or ASR timing provenance.
- A `SpeechEvidenceRun` preserves the source engine/model, thresholds, normalization/segment-rule versions, canonical absolute sample boundaries, and unavailable/failed status. Its leading/trailing silence is not counted as pause unless a versioned metric rule explicitly says otherwise.
- Deterministic metrics own stable, directly measurable facts. They share their Common definitions across Free and Structured training, record threshold/algorithm versions, and do not ask AI to re-measure those facts.
- `AnalysisContext` is a bounded, versioned input assembled from the applicable facts, evidence and MetricRuns. AI may interpret it, but a validated Finding must retain references to the evidence actually supporting its observation; an invalid schema or unknown reference makes that AI result locally unavailable rather than inventing a replacement.
- A Finding uses `Observation → Interpretation → Recommendation`. Recommendation can suggest a Finding-aware next action but never directly starts, scopes, or selects a Retake; the user action and resulting new Session remain separate.
- 主 ASR 结果归属该 Session 的 transcript/segments，模型、版本和 timing 能力归属 ASR 来源快照；后续切换模型不重写已保存事实。SenseVoiceSmall 的角色按 [R-A10](../product/requirements.md#6-m2表达证据ai-分析与雷达图)，不另建辅助转写实体。
- AI result status is independent of session completion: unavailable/failed states do not change completed facts. Scheduling and enablement follow [R-A04/R-A11](../product/requirements.md#6-m2表达证据ai-分析与雷达图).
- A Structured session automatically requests Framework Analysis for its selected framework in addition to Common Analysis.
- A user may explicitly request a framework re-analysis of an existing session. That appends a new `FrameworkAnalysis` over the same transcript revision and evidence; it does not change how the session was trained.
- AI Coaching consumes facts and validated Common/Framework results to explain priorities and suggest improvements. It is not an independent source of deterministic facts or scores.
- 每次继续练习/重练均创建新的 `TrainingSession`，包括句子/片段/完整表达范围的 Free 重练；自动保存新事实与新结果，不复用源 Session identity，不覆盖原表达、原分析或此前 attempts。
- Finding-aware 重练的新 Session 必须持久化来源 Session 与来源 Finding 的关系。Finding 引用应能定位其所属来源 Session 和分析结果/版本，不能仅靠显示名称或当前页面状态识别。
- 来源关系记录训练意图与前后关联，独立于 `trainingMode`、framework 和训练题目，不产生独立 Session 类型；继承的准备值在新 Session 开始时形成它自己的事实快照，不引用一个可变的源上下文替代快照。继承与用户调整流程由 [Training Flow §9](../product/training-flow.md#9-带上下文再次进入-training-workspace) 定义。History 不展示上/下游报告不取消这些关系或持久化义务。
- Practice Chain 的产品语义由 [Training Flow §10.2](../product/training-flow.md#102-多轮练习历程) 定义。M4 用每轮不可变的 `practice` 关系快照恢复目标、轮次和前轮，不新增通用链实体。快照含 `chainId`、`round`、`scope`、`goal`（来源观察/建议/类别）、`origin`（来源 Session/Report/Analysis/Finding ID 与定义版本）、`previousSessionId` / `previousReportId`，以及按轮次排列的 `history`（Session/Report ID、轮次）。第一轮为基准；历史只存定位元数据，不复制来源录音或逐字稿。Main 从真实已保存的来源 Finding 构造快照，不接受 Renderer 自报轮次或链事实。
- Session identity 不等于链成员 identity：某记录可在旧链是末轮，同时被新链历史引用为第 1 轮。沿当前目标继续时保留链和 origin，更新相邻 Session/Report 引用；改选 Finding 新建链。来源删除后保留最小定位元数据及本轮练习目标，不级联后续练习；缺失来源按 Flow §10.2 降级，不能用另一条记录补位。
- Training-time Guidance is framework-definition content shown before a session. Post-training Framework Analysis is versioned derived output. They may share a definition but not a storage record or UI responsibility.

M4 的专项结果嵌入不可变 `diagnosis.value.frameworkAnalysis`，记录 framework、definitionVersion、summary 和带引用的 findings，复用所属 run 的 status/analyzerVersion/inputRevision。`analysisTarget` 与 Session 的训练方式分开；显式框架重分析追加 Diagnosis / Report snapshot，复用已有 Speech Evidence / Common Analysis 的确切 ID。v10 新诊断不含 `frameworkRecommendation`；旧字段仅作历史读取兼容，报告不再展示或提供采用动作，历史结果保持不可变。

针对性练习的 `practiceFeedback` 保存状态、结论、前一轮和本轮转写引用；非 unavailable 结论必须两侧有证据。它只回答已选目标，不承担 B-25 的任意历史 Finding 自动对应。删除来源后既有派生快照保持不可变，展示时检查引用可用性并降级，不能把不可复核的历史结论继续作为当前改善证明。

v6 新反馈还必须有 `comparability:{status,reason}`，status 为 comparable/unavailable，reason 为 1～800 字符；模型平铺返回 `comparisonStatus / comparisonReason`，Main 校验后组装该保存形状，不混用两套表示。先判断所选目标是否有足够的前后材料，再产生变化状态；不可比较、当前材料不足、来源不可用或摘要/比较理由明确无法判断目标变化时，只能保存 unavailable，并使用同一限制形成摘要。对显式无法判断语句的保守检查只做降级，不推断改善，不将局部练习对全文的限制扩大为目标不可比，也不能替代语义验收。句子/片段练习不保存完整框架评价；移除该评价后若没有可评价类别，归为当前范围材料不足，不能保存不可读取的 completed 结果。保存期间删除来源时同时降级变化状态和可比性；旧反馈缺少该扩展仍按既有来源检查读取。

## 8. Write and recovery protocol

自动保存要求见 [R-P01/R-P05](../product/requirements.md#5-m1训练记录持久化)，用户反馈见 [Training Flow §6](../product/training-flow.md#6-自动持久化与分析状态)。这里定义写入完整性；不要求持久化每个 ASR partial。

The exact API may change, but these invariants do not:

1. Create a session in `recording` or `finalizing` before publishing it as completed.
2. Write audio to a staging file under the managed data root.
3. Flush and close the file, compute/record integrity metadata, then atomically rename it to its final relative path.
4. Commit the final transcript, stable segments, source snapshot, artifact state, and `completed` session state in one database transaction.
5. A crash before step 4 leaves an `incomplete` session or reclaimable staging file, never a healthy completed record.
6. Startup recovery marks missing/corrupt artifacts explicitly and may remove only unreferenced staging files according to a documented age rule.

Implementation must be idempotent for a repeated finalization request with the same session ID.

## 9. Read, delete, and migration semantics

- History queries order sessions by `createdAt` descending and use a stable secondary key; user-visible naming/navigation belongs to Training Flow §13.
- Reading one corrupt record does not prevent healthy records from loading.
- Deleting a session removes its managed artifact files and database-owned children. Partial failure remains visible and is retryable.
- Schema migrations are numbered, forward-only, and transactional where supported.
- A database from a newer unsupported schema is opened read-only or rejected with a clear error; it is never silently downgraded.
- M1 保留策略按 [Requirements §5.1](../product/requirements.md#51-m1-保留与起始边界)；后续容量提醒按 [Requirements §9.1](../product/requirements.md#91-已确认的后续容量提醒策略实施待排期) 执行，不是硬配额，也不授权自动清理；提醒状态不属于训练事实。报告复制/导出/分享与备份见 Backlog D-11，不扩展 M1 schema。

## 10. Comparison invariants

这些逻辑约束让 M1 事实可用于后续比较，不要求 M1 实现 comparison 子系统。重练轻量对比与历史完整对比共享同一个 `Comparison` 概念：显式引用基线/目标 Session、比较范围、证据与分析版本；UI 容器不产生另一套比较事实或评分标准。具体 schema/API 留待对应里程碑。Comparison 的两个 Session 引用与基线/目标角色须明确；查看任一侧报告不改变原比较对象。Comparison reads the selected stable Report/result versions and never triggers an implicit historical re-analysis. UI 的入口、返回来源和展开/滚动状态由 Training Flow §13 定义，属于展示/导航上下文，不因此新增 Session 事实字段或 M1 比较表。

比较按指标/证据项判定为可比、需归一化或不可可靠比较，不因其中一项可比就推断整份报告都可比。归一化必须声明口径和分母（例如按分钟或字数的口头禅频率），仅在范围有意义且事实支持时执行；保留原值，不把句子、片段与完整表达的总量差异当作进步。无法建立可靠对应关系时说明限制，不强行生成改善结论。

不同 framework 的两个 Session 可以成为同一 Comparison 的输入；以下同 framework 条件只限制特定比较项，不构成整对 Session 的拒绝条件。缺失/不可比项与可用项的结果应可分别表达；D-13 的 M3 兼容性细化见 §10.1，规则已按首版范围冻结，交付证据以 M3 milestone 为准。

版本与证据约束：

- Fact-to-fact comparisons may use raw duration, text, and shared timing evidence.
- Common metric or radar comparisons may cross `trainingMode` when they use the same `definitionVersion`, or when both sides are recomputed with one compatible version.
- Framework-specific findings or scores are comparable only when both sides use the same `framework` and a compatible `analyzerVersion`; PREP, STAR, and Pyramid scores are never treated as one shared scale.
- AI model output from different providers/models may be shown side by side but cannot alone establish user progress.
- Missing audio/timing/evidence produces an explicit non-comparable state for the affected comparison item; remaining supported evidence can still be inspected. Missing values are not zero.
- If calculation provenance is incompatible, the affected item has no deterministic change conclusion. “Not comparable” is neither improvement nor regression.

#### 输入与快照

- 输入为两个不同的已保存 Session，明确 `baseline` / `target` 角色。比较范围由实际事实与可用证据决定；不同 topic、mode 或 framework 不拒绝整对输入，但不能把任务差异消除后再声称能力改善。
- 进入比较时按既有稳定 Report 选择规则取得两侧快照，固定 Session ID、transcript revision、Report result ID 及其精确 Source/Metric/Diagnosis 引用。旧记录无结构化 Report 时保留可用事实，分析缺失局部说明，不自动补跑。比较期间新增结果不能悄悄替换已固定输入。
- M3 首版采用只读 Comparison 投影，不新增 SQLite 表或持久化第二份报告。界面保留本次输入与查看上下文；退出后再次从 History 发起时重新选择当时的稳定快照，不承诺跨应用重启恢复未完成的比较任务。今后确有保存/分享比较的需求时再扩展持久化。
- Evidence 引用必须携带所属侧、Session、revision 与实际 Run；`speech-1`、`metric:…` 或 Finding ID 相同不表示跨 Session 的同一对象。删除、损坏或引用失效时停止依赖该证据的结论，不换成另一条记录、另一个 Run，也不从缓存恢复已删除事实。

#### 逐项兼容性

先检查每侧值与引用有效，再判断两侧口径；不能只检查版本字符串相等。默认只接受已知的 V1 schema、Metric ID/单位与 producer 定义，未知版本不猜测兼容；首版不提供自动重算或版本转换。`analyzerVersion` 相同本身也不是质量或可比性保证。

| 比较项 | 首版判定 | 可输出的变化与限制 |
|---|---|---|
| 录音时长、已保存原文与字符总量 | 有效事实可并列；完整范围和同一计量口径下可展示客观总量差异 | 说明比较的是录音/转写观察；更短、更多字不代表更好。不同 ASR 来源不妨碍读原文，但须标识识别差异可能影响文本 |
| 词项命中次数 | `definitionVersion`、单位、有效统计输入及当次词表一致；默认词表/匹配规则以已知定义版本识别，自定义词表使用已保存快照判断；缺失身份不采用今日设置补齐 | 可展示总量差异；表达时长/范围不同不能由次数降低推断习惯改善，频率复盘使用下一行已存在的指标 |
| 每录音分钟字符数、填充词命中频率、两个字符占比 | 使用 §5.3 已保存的相同分母定义；所依赖文本、词表、音频覆盖均有效。用于解释表达变化时还需已知且兼容的 ASR producer/model 来源；未知或不同来源只并列观察并说明限制 | 明确标为按录音分钟或字符归一化，不把两种分母互换。保留原值与分母依据，不新增第二套历史统计 |
| VAD 语音/非语音时长、内部间隔次数/总时长/最长间隔 | 完整覆盖且 Source/Metric 链有效；`engine`、`engineVersion`、`modelId`、`modelVersion`、`modelSha256`、`thresholdVersion`、实际 `thresholds` 与 `normalizationVersion` 全部已知且一致 | 可比的是同一检测方法的观察差异；未校准状态始终可见，不据此评价流利度、长停顿或能力。总量受表达长度影响；不为首版增加新的间隔频率指标 |
| 每检测语音分钟字符数 | 同时满足文本来源、转写覆盖与上一行 VAD 兼容条件，且检测语音分母为正 | 明确“字/检测语音分钟、非逐字对齐”；不能与含静音的“字/录音分钟”相减 |
| Framework 分析 | 同 framework、同 framework definition 且 analyzer 已有明确兼容依据；首版无兼容转换表时只认已知相同版本 | 不同框架局部不可比；M3 不提前交付 M4 的框架分析 |
| 雷达 | M2 快照为 `uncalibrated / unavailable` | 保持不可用，不画比较多边形，不把四类 Finding 转为数值轴；完整校准仍归 B-20 |

同一 ASR/VAD 来源不保证测量正确，只限定可解释的方法一致性；缺失与质量限制继续按依赖传播。单纯没有 token timing 不阻断文字总量或有效的全段速率。

比较结果逐项表达“可比 / 需归一化 / 暂时无法可靠比较”、理由、两侧原值、证据与适用的差值。归一化只使用上表已定义的速率/占比及其有效分母；条件不足时降为不可可靠比较，不能先计算一个看似精确的结论。差值统一为目标减基线；占比差使用百分点，零基线不产生无穷大或相对百分比改善。语速增加、时长减少、命中率下降首先是观察变化，没有目标/解释依据就不加“更好”的评级。

#### Finding 对应与变化结论

现有 `FindingV1` 的 ID 只在所属结果内有意义，没有跨录音的问题身份。四类类别用于组织内容，不作为“同一问题”的匹配键；同类、相似文案、相同局部 Evidence ID 或目标侧未返回 Finding 均不足以证明持续、改善、新出现或已解决。同 provider/model/prompt 只能减少来源差异，仍不能单独建立上述结论。

M3 首版依据可靠指标解释客观变化，两侧 Findings 保留来源与 Evidence 供复盘；语义对应不足时明确“暂时无法可靠比较”。不推断问题改善、持续、新出现或消失。该语义判断能力及双录音 AI 比较延期至 [Backlog B-25](../product/backlog.md#not-now)，R-R02 已明确首版验收边界。

## 11. M1 non-goals

- Full event sourcing or persistence of every partial ASR event.
- Generic entity/plugin storage.
- Cloud-compatible sync identifiers or conflict-resolution metadata.
- Vector databases or embeddings.
- Detailed schemas for conversations, comparisons, framework attempts, or future prosody features.
- Moving existing settings/model stores into SQLite.
- Compatibility storage for pasted-text sessions; the target product starts persistence with microphone sessions only.
