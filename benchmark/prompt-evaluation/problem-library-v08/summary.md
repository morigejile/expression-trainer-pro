# 第一批质量收尾：v7 基线与 v8 候选对照

## 1. 基线、版本与实验身份

- 本轮基线是上一轮最终 `structured-diagnosis-v7`／问题库 v0.3，不是更早的 v6。[冻结源码及校验值](baseline/manifest.json)保存了四个当时未提交的运行时文件，以及原 refined 请求、输入和预览的 SHA-256。原 [refined 输出](../problem-library-v03/refined/actual-results.json)及预览未覆盖、未改写。
- 最终候选是 `structured-diagnosis-v8`／问题库 `expression-problem-library-v0.4`。[最终版本清单](final-manifest.json)固定各案例系统文本的校验值；之后没有边跑边改同一提示版本。
- [筛查结果](screening/results.json)是 20 次真实请求：基线 7、任务门槛单独调整 5、去逐卡练习方向 4、短合并示例 4。[最终结果](final/results.json)是补齐基线 5 次及最终候选 26 次。共 **51 次实际模型请求**，不是模拟返回。
- 变体名分别为 `structured-diagnosis-v8-exp-task / exp-lean / exp-merge`。它们以冻结 v7 为底，仅叠加各自因素：task 使用 v0.4 的任务门槛与 ORG-08；lean 只删除逐卡练习方向；merge 只加入短对照。其原始问题库标签保留 v0.3 基底，组件差异由实验名、上述定义和完整请求文本标识，不把这些混合变体称为最终 v0.4 生产提示。
- 最终 v8 合并三项调整，并合并部分重复的固定证据说明。单因素未证明可靠内容收益；选择组合是本轮有界候选，不代表已证明它是最佳组合或已定位根因。

[最终提示词可读展示](final/prompt-preview.md)标明固定规则、动态卡片、条件练习规则，并将本次合成上下文重建成人类可读形式；完整字段仍在 [最终输入与校验值](final/inputs.json)。

## 2. 控制条件与审阅方法

所有请求使用既有已授权配置，请求模型名均为 `deepseek-chat`，响应 `model` 字段均为 `deepseek-flash`；不推断服务端别名映射。temperature=0.2、max_tokens=8192、DeepSeek JSON Output、60 秒上限，没有自动重试或第二次模型审核。没有使用真实用户录音、写配置、切换服务或开启服务。

每个案例在各变体间保留完全相同的用户消息与参数，按输入哈希核对；没有截断原文、缩减字数或把人工预期发送给模型。普通观点／执行安排对照只改任务，同一正文不变。其余反例是明确给定的新合成输入，不把不同正文之间的差异解释成单因素因果证据。

为分离格式与内容，所有组实际返回都用同一 v8 解析器检查，同时保存 `strictV7Format`，表示冻结旧解析器对同一 raw 是否接受。`raw`、`parsed`、`normalizations` 分开记录；失败返回不会冒充成功报告。原始记录还包含完整系统／用户文本、版本、采样参数、请求／输入哈希、usage、响应模型名和耗时，不保存认证头、密钥或完整配置。

下列内容结论由本助手阅读实际输出后对照人工预期作出，不是程序按 Finding 数量自动评分，也不是多人标注的准确率基准。筛查每格仅一次，不估计稳定误报率。

## 5. E06 格式兼容的准确边界

仅当可信上下文已选中有效框架及有效定义版本，且平铺返回没有 `frameworkRecommendation`、按规则该字段只能为 null 时，解析器补这个字段。随后继续全部严格校验；只在整体成功后发出接受的补全回执。

- 不为 Free 的平铺新响应普遍补字段；旧嵌套结果沿原兼容规则读取，不迁移历史。
- 不覆盖已有非 null 值，不补 assessment、摘要、Finding、框架摘要或引用，不接受未知字段、非法类别、重复 ID、空引用或其他缺失。
- 不触发第二次 AI 请求，不修改原始字符串。最终报告仍只有既有字段。
- 现有 provenance 增加可选 `responseNormalization`：固定 code／field、value=null、原始 `rawResponse`；原始字符串限 64,000 字符，四个字段精确校验。旧结果保持缺失，不新增表或独立持久化体系。
- 原 refined E06 的真实旧 raw 离线重放：旧解析拒绝，新解析补 null 后接受；原来的两条通用、两条专项发现原样保留，内容问题没有被清洗掉。模拟 HTTP 验证单次调用与 raw／回执转发，SQLite 验证来源保存、重开和旧结果兼容。
- 本轮 51 次实际请求中，没有返回触发这一窄补全的情形；50 次解析接受、1 次基线 E06 因另缺 Finding.evidenceRefs 被拒。最终 26 次恰好全部提供了所需格式，不能把它们的成功归功于补 null，也不能宣称格式失败全面解决。

## 7. 本轮保留的结论

实现和实验记录已形成可审阅结果；v8 是已接入源码的质量候选，**不标记为内容验收通过**。任务对照有符合预期的表现，输入量确实下降，原 E06 的特定缺字段有受限兼容；但 E03、E06、E07 及空泛行动的重复、过度追问和分类波动仍在。没有证据支持“冗长是根因”“去练习方向就能解决”“短示例保证合并”等强结论，也没有基于本组结果修改原人工预期。

主报告仍只做一次模型诊断；程序不承担通用语义去重。上一轮比较证据、旧报告、回放、词表、15 项指标、页面跨组排序均未扩展。本轮修改未提交、未推送。
