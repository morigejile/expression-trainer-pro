## 误报、漏报、重复与事实保留

- **误报**：最终 E01 仍有；E04 的额外具体化要求未能证明当前简短建议任务确实受阻。E06 raw 仍偏向要求更多行动细节，不能作为通过结果。
- **漏报**：已接受的新结果中，E03 主张缺失、E04 结论位置、E05 因果跳步、E07 重启等核心预期均有检出。但本组覆盖范围很小，不能由此推断问题召回率或宣称无漏报。E06 是协议失败，不能混算成“没有问题”。
- **重复**：E03 仍重复。E06 raw 的通用／专项仍存在相近缺口重复。程序没有承担或保证语义合并；不同措辞、不同 ID 仍可能表达同一训练目标。
- **事实保留**：最终 E02 没有要求删掉条件。有效新版结果的表达参考仅 E04 非空，使用原有完整分句重排，本次审阅未见新增事实。建议中的条件、例子和待补信息仍须由用户确认；不能由引用合法或参考字面匹配推断普遍语义保真。
- **能力边界**：这组没有声音证据。最终有效新输出未断言精确停顿、重音、局部语速或心理原因；这仅是本组观察，不是声学禁评永远生效的保证。

## 成本、顺序与结论限制

本次最终对照的 API usage 显示，旧提示输入为 2,829～3,439 tokens，新提示为 8,839～10,182 tokens。问题卡带来明显输入开销；不能仅凭内容集中维护就声称性能改善。本次没有扩大输入上限、压缩转写、修改输出 token 上限或切换模型。样本长度、缓存命中、服务波动会影响成本和耗时，不把单次耗时外推为稳定速度。

新提示只要求每个返回数组内部体现关注重点。现有页面仍先通用后专项并截取前两条／旧布局前三条；即使模型认为专项更重要，也不能据此声称真正跨组优先排序已完成。本批未改页面或排序契约。

可确认的是：问题卡和排除／合并规则已进入真实主诊断请求，结构与历史兼容有独立自动化验证，且完成了上述受控真实对照。不能确认的是：全部 E01～E08 内容预期通过、可靠的语义去重、总体误报率下降、模型稳定性或训练效果已经成立。E01、E03、E06 是后续内容质量验证必须保留的反例。

复跑方式：使用 Node 24.20.0 执行 `scripts/evaluate-problem-library.js`。默认只写合成输入和可读提示，不调用服务；只有显式 `--live` 并指定当前 user-data 目录、输出目录和基线 revision 才请求当前已授权配置。每次应另指定证据目录，保留原始结果；不要覆盖旧实验来制造“全部通过”。
