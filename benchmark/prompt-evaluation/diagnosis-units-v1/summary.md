# 问题单位、任务标准与生成结构实验

日期：2026-10-31。**建议保持生产默认 v8／问题库 v0.4，不采用本次统一列表或二次复核作为默认流程。**实验实现已可审阅；有限内容结果呈现局部改善与退化，未证明语义诊断可靠。本轮未提交、推送或改变生产主报告入口。

## 身份、顺序与控制条件

- [基线身份](baseline/manifest.json)冻结 10 个相关生产源文件及上一轮 v08 四份证据的字节哈希，源码副本在 baseline/sources；[基线实际请求](baseline/requests.json)保留上一轮最终 26 份系统／用户文本与版本。离线核对当前组装的 v8 系统文本与它们一致。不是从 HEAD 猜测未提交基线。
- [评审标准](rubric.md)、[合成输入](datasets.json)及[预注册](preregistration.json)在生成本轮结果前固定。明确缺陷／已满足／可选深化／证据不足是研究标签，不新增产品字段或评分。必要性也来自主动声称的“唯一原因”，不局限于题目逐字要求。
- 首轮为 `diagnosis-units-v1` 与独立 `diagnosis-scope-v1`：[17 次筛查](screening/results.json)。筛查源码另存在 screening/source，原结果不覆盖。
- 测试发现：已明确映射为 argument 的多类型单位，校验时仍取第一个类型的类别，导致 types 顺序影响 assessment 校验。先用失败测试复现，再修复，单独冻结为 `diagnosis-units-v1.1`，见[候选身份](candidate.json)及 candidate-source。除系统版本字符串外，统一列表系统文本未改变；离线程序逐例验证了这一点。没有借修复适配器同时改写内容规则。
- 最终候选固定后完成[40 次对照](final/results.json)：15 个案例各做 v8／v1.1 匹配对照，E03、E06、E07、同片段独立问题、H03 再各做一组匹配重复。最终版本每个重点案例两次，首轮 v1 不混称 v1.1 重复。H01～H03 为未用于提示调试的新正文；H04 是预注册的局部范围预试，不冒充最终未见案例。rubric 的“新案例封存”标题涵盖 H04，但实际调度以预注册的 scopePretest 为准，此差异在此明确保留。
- 单调用在 E03、E06、空泛行动仍持续失败，达到预注册门槛后，仅做[4 次第二步复核](review/results.json)。它们复用筛查的实际 v1 候选，第二步为 v1.1-review，不把两者混称同版本两次生成。第一步来源、返回哈希、模型名、两步合计开销均记录。

共 **61 次真实模型请求**。全部使用既有已授权配置，请求模型 `deepseek-chat`，响应 model 为 `deepseek-flash`，不推断服务端映射。temperature=0.2、max_tokens=8192、JSON Output、60 秒上限、无自动重试。未写配置、换模型、开服务或使用真实用户录音。匹配组保留相同输入与参数；普通观点／执行安排只改任务，正文相同。没有把评审标准或预期答案发送给模型。

所有组先阅读随机打散、隐藏版本／类型／类别的内容，再写入各目录 blind/review-before-unblinding.json，之后关联 key。研究评阅仍由本助手完成，文风可能泄露版本；**不是独立人工验收或多标注者评测**。独立代码审阅只检查实现与契约，不替代内容评审。

## 已确认发生层与未证实原因

| 层 | 可直接确认的证据 | 不能据此宣称 |
|---|---|---|
| 原始生成 | 上轮 v08 E03 第1、2次和 E07 的重复已在 raw.findings 内，frameworkFindings 为空；本轮 v8 仍可见同数组重复 | 双数组是所有重复的根因 |
| 任务标准 | 同文 E01 不要求执行安排、执行题检出安排缺口；但 E06 把中间发现／后续状态提升为必需，H02 把正常条件及未定事项升级为关系缺口 | 所有补充建议都错误，或“完整答复”必然要求所有细节 |
| 问题单位 | E03 统一列表仍将选择缺口、结尾落点拆两条；空泛行动仍将具体性与任务对应拆两条 | 去掉两个数组或增加类型标识就可靠语义去重 |
| 分类与归属 | 给定一个有效类型，程序可确定映射；但 E03 重复分别选 ARG-01／ORG-01 或 ORG-08，独立冗余两次选 ORG-05／WRD-06 | 类型映射消除类型选择或语义分类的波动 |
| 格式 | 本轮 61 份返回均通过各自结构验证；筛查有1份类型跨类别无法明确映射，保留限制，不作为成功报告 | E06 内容通过、格式全面解决、未映射等于无问题 |
| 页面 | 当前冻结页面把通用数组接在专项数组之前再取前2条；非冻结分支沿既有分区。程序适配会丢失原统一列表的跨组交错顺序 | 页面导致了模型原始重复，或实验已保证全局优先顺序 |

提示长度、模型能力与双数组均仍是原因假设，未定位为单一根因。本次“统一结构”包含类型字段、输出约束和分组适配这个整体，不是对 JSON 数组数量的纯粹单因素因果证明。v8 的 task／卡片语义主体保持不变；本轮未另做任务标准措辞消融，不能宣称已找到解决过度要求的规则。

## 实际交互结构与程序边界

[人类可读提示词](prompt-preview.md)展示相同 E06 输入下 v8 与 v1.1 的完整实际系统文本，区分固定规则、动态卡片、真实材料和条件练习规则，并展示独立局部变体及复核要求。

v8 让模型分别生成通用与专项数组，每条自己给类别和 ID。实验只要求一份 discoveries，每条为一个障碍，含支持它的类型编号、原文证据、简短依据、建议及可选表达参考。模型不输出单条类别、分组或最终 Finding ID，不输出详细思维过程；assessment 继续声明可评价维度。

[实验适配器](adapter.js)仅使用本次实际注入的卡，拒绝未知、不可用声音、外框架及局部完整框架类型。按类型映射四类；有所选框架类型时归专项。ARG-01 与 ORG-01／ORG-08、ARG-06 与 PREP-04 的单单位联合支持有明确归属规则；其他跨类别联合支持无法确定时保留完整发现、引用和限制，readyForReport=false，不能伪装为无问题。最终 ID 使用 common-unit-N／framework-unit-N，库编号不替代 Finding ID。

程序只删除字段、支持类型及引用集合均完全一致的节点；不会按同编号、类别、片段或相似度合并。本组没有靠程序删除语义重复。筛查同片段独立案例生成 ORG-05＋WRD-06 联合支持时无法明确分类，实际输出及 partialAdapted 均保留，未硬选一类。最终两次分别选单一类型，能够适配，但这不是该歧义已解决。

最终仍经现有严格解析返回既有 Report／Finding／Practice 结构。材料不足、证据范围、框架和局部限制继续生效；这些结构检查不能验证推荐中的事实或缺陷必要性。适配器不从生产入口加载，没有新数据库、持久化字段或历史迁移。

局部范围变体只按 practiceComparison.goal 的完整观察／建议和实际 scope 检查目标，保留完整原始上下文，不按类别或关键词筛选、不猜库编号。使用旧 v8 输出结构，不叠加统一列表。E07 输入由9,078降至6,307 tokens，但发现从基线2条变3条，分别称要点未定、重启、自我修正，仍共享一个动作；H04 正常局部开头两组都空。**两例不支持“减少卡片即可使目标收敛”**，不把变短当质量收益，也不推断所有目标都会退化。

## 建议

保持生产默认 v8，保留本实验作为可重放证据。统一列表让问题类型与分组职责更清楚，并在 E07、同片段独立障碍、新因果例中看到有限收益；但 E03 重复、E06 任务标准、E02/H02 正常反例、类型选择波动与未映射限制均阻止现在切换。当前二次复核也没有足够收益，不建议继续扩大同一方案调用量。

仍可研究的是如何在生成单位之前明确“任务已满足／必要缺口／可选深化”的区别；本轮只先固定评阅标准，没有证明某个运行时实现能可靠完成该区别，不把它写成已解决能力。本次没有需要改动产品语义或对外契约的未授权决定；若以后将未映射发现接入产品，必须单独确定如何呈现限制，不能直接使用实验的部分结果冒充完整成功报告。
